# 门户面板「更多设置」入口 方案 (2026-11-13)

## 0. 一句话

门户右上 `⋯` 里那两张面板 (判断 / 探索) 现在**只读**: 看得见"冷却 30 分""下一趟还没排", 却要退出去开
设置页才能改一格. 这一轮在**两张面板的最底部**各加一行「更多设置 ›」, 点开一个**原生弹窗** —— 壳就是
`SimSettingsDialog` 那个 `OverlayDialog` (与新手引导里选权限同一副), 内容 = 设置 → 活动那一整块:
探索 / 主动对话 / 开口节奏与判断 / 表情. 入口只有两个, **不进 `⋯` 菜单** (主人 2026-11-13 定);
读写仍只有一份表, 门户那层一个字节不写盘.

## 1. 口径: 主人这一轮定的

> 不用加在「更多」那个窗口里, 只要在探索和判断面板中的最底部即可.
> 「更多设置」弹出窗口显示 luwi 设置中活动板块的相关设置, 窗口用像新手引导中权限设置那样.

三条硬口径:

1. **入口位置**: 判断面板与探索面板的**最底部** (动作行之下), `⋯` 菜单保持三行不动
2. **窗口形状**: 原生弹窗, 与新手引导里选权限那副同一个壳 (`OverlayDialog`), 不是二级页、不是网页里画的卡
3. **内容**: 设置 → 活动 板块里**探索与主动对话相关**的那些参数

### 1.1 追加口径 (2026-11-13 晚): 一律说「唤醒」, 不再说「敲钟」

> 敲钟改成唤醒.

四条分寸:

1. **范围只到文案**: 门户判断面板那行读数与两颗按钮、`settings_sim_*` 那几条说明、在用文档的措辞。
   `RouterTick` / `router.json` 的 `tick.enabled` / `sim.json` 的 `wake` 段 / 桥方法 `portalTick*` /
   `lw_router` **一个都不改** —— 盘上结构零变化, 改的只是人看见的字
2. **为什么顺**: `sim.json` 那一段本来就叫 `wake` (`gapMinMs` / `gapMaxMs` / `mode` / `preSleepWaitMs` /
   `quiet*`, 见 `tool/SimSetting.kt` 的 `SimSetting.Wake`), 球与宿主口头也说"唤醒"; "敲钟" 只是界面上
   的孤岛词, 改掉是与内部命名对齐, 不是新造概念
3. **撞词只两处, 有现成边界**: 设置页「唤醒」那一段是**语音唤醒词** (`settings_section_wake` /
   `settings_wake_*` / `settings_lock_auto_unlock`)。这一轮不碰那一段, 新文案里也**不出现"唤醒词"这个
   组合**, 所以不会串
4. **与 2026-11-10「去群味」那一条的冲突照新口径解**: `check-sim.mjs` 原有一条负断言
   `!simLines(zh).includes('唤醒')` (当时把「唤醒」也算群味词)。主人这一句把叫法定成「唤醒」, 那条
   断言直接冲突 —— 以主人为准撤掉它, 只留 "Diving and waking" 那句英文长句与第一段的标题
   (`tools/check-sim.mjs` 那一节里写明了原因)

改前 → 改后:

| 位置 | 改前 | 改后 |
| :-- | :-- | :-- |
| 判断面板读数行 | `敲钟` | `唤醒` |
| 面板两颗按钮 | `敲一下钟` / `打开敲钟` / `关掉敲钟` | `唤醒一下` / `打开唤醒` / `关掉唤醒` |
| `settings_sim_note` | 敲钟之后看什么… | 唤醒之后看什么… |
| `settings_sim_mode_summary` | 潜水 = 不主动敲钟… | 潜水 = 不主动唤醒… |
| `settings_sim_gap_min` / `_max` | 敲钟的最短 / 最长间隔 | 唤醒的最短 / 最长间隔 |
| `settings_sim_pre_sleep_summary` | 她这一拍就不敲 | 她这一拍就不唤醒 |
| `settings_sim_quiet_summary` | 这一段里敲钟照敲 | 这一段里照常唤醒 |

英文侧同口径 `tick` → `wake` (与 `sim.json` 的 `wake` 段一致)。§2 那几张表引的是本轮改前的字面量,
与上表对照着读; 代码注释里那一批「敲钟」一并改成「唤醒」, 只动注释不动标识符。

四点分寸:

1. **按钮位置由主人点名**: 动作行 (`lwp-actions`) 的第三颗, 排在「打开/关掉唤醒」与「刷新」右边 ——
   不进 `⋯` 菜单, 也不在抽屉最底下另起一块. 抽屉本来就会换行 (`flex-wrap: wrap`), 窄屏也不会被裁

   同一张面板 —— 不用来回点
3. **读数一行不动**: 面板上那几行照旧, 关窗时宿主推一句 `onSettingsClosed`, 页面把 `portalStatus()`
   重拉一遍, 于是"冷却改成 45 分"当场就能在面板上看见
4. **弹窗里只有能改的**: 读数 (上一次判断 / 下一趟 / checks 状态) 不搬进弹窗, 读写分得清

### 4.1 焦点滚动: 一组 = 一个 `item`

别按 item 下标写魔法数 (改一行就错位). 一组 = 小标题 + 卡片 = **两个 item**, 下标只由这两张表算:

```kotlin
/** 设置页那四个入口的顺序 (一组 = 小标题 + 卡片, 两个 item) */
private val SIM_GROUPS = listOf("wake", "send", "router", "sticker")

/** 门户那两颗「设置」多出来两组, 摆在最前面; 加组只改这两张表 */
private val ACTIVITY_GROUPS = listOf("explore", "proactive") + SIM_GROUPS

private fun groupIndex(focus: String, withActivity: Boolean): Int {
    val groups = if (withActivity) ACTIVITY_GROUPS else SIM_GROUPS
    val wanted = when (focus.trim()) {
        "explore", "proactive", "router" -> focus.trim()
        else -> "top"                 // 认不出来的词从顶上开始, 页面不用处理失败分支
    }
    val at = groups.indexOf(wanted)
    return if (at <= 0) 0 else at * 2
}
```

```kotlin
val listState = rememberLazyListState()
LaunchedEffect(focus, withActivity) {
    val index = groupIndex(focus, withActivity)
    if (index > 0) listState.scrollToItem(index)
}
```

`scaffolds/LazyColumn` 本来就收 `state`, 不用为它改那一层.

### 5.1 `ui/PortalAsk.kt` (新增, 三十行)

```kotlin
internal object PortalAsk {
    /** 弹窗的焦点词; 读它就会跟着重组, 关掉时置回 null */
    val activitySettings = mutableStateOf<String?>(null)

    fun ask(focus: String) { onMain { activitySettings.value = focus } }
    fun close() { onMain { activitySettings.value = null } }

    /** 桥回调在 JavaBridge 线程上: Compose 只认主线程那一次快照, 所以 post 一下 */
    private fun onMain(block: () -> Unit) {
        if (Looper.myLooper() == Looper.getMainLooper()) block()
        else Handler(Looper.getMainLooper()).post(block)
    }
}
```

**没用 StateFlow**: 这一层不需要背压也不需要多听众, 一个 `mutableStateOf` + 主线程写就够; 组里读它的
地方只有 `HostScreen` 一处 (`PortalAsk.activitySettings.value`), 读即订阅.

## 6. 唯一实现约束

三个入口 (设置页 / 判断面板 / 探索面板) 共用**同一份** `SimSettingsDialog` —— 实测下来最省的做法是
**给它加两个默认参数**, 不另开第二个弹窗壳, 也不新建 `ActivitySections.kt` (那种拆法要挪动几百行,
换不来任何判据上的好处):

| 动作 | 做法 |
| :-- | :-- |
| 一份弹窗 | `SimSettingsDialog(onDismiss, focus = "top", withActivity = false)`; 设置页那个入口一个参数都不加 |
| 两组搬入 | `ExploreItems` / `ProactiveItems` 从 `private` 改 `internal`, **留在 `SettingsScreen.kt` 原地** (同一 package, 弹窗直接调); 门户侧用 `Card { Column { … } }` 包一层 |
| 两个附属弹窗 | `ProactiveActingPicker` / `ProactiveActingConfirm` 原样跟着 `ProactiveItems` 走, 没改可见性 (它们在同一个文件的同一段里) |
| 调用方 | `SettingsScreen` 活动段 (四组) 与门户弹窗 (六组) 都调这一处 |
| 写的路 | 仍只有 `ExploreSchedule.save` / `ProactiveSchedule.save` / `SimSetting.save` / `RouterTick.setEnabled` 四条 (判据 `check-activity-settings` 钉住 `ui/` 里没有第二份参数页, 设置页也只有主动场那一处写 `sim.json`) |

## 10. 风险与备选 (实测之后)

| 风险 | 处理 |
| :-- | :-- |
| 弹窗里叠弹窗: 静默起止 (`TimeTextDialog`) 与「能做什么」两档都是二层 `OverlayDialog` | 从门户进来会成三层; 实测不崩 (Miuix 的 Overlay 各自一个 Window), 但**改静默起止那两下要到设置页去改**的那句还没加 —— 真机上量到不稳再动手 |
| `ExploreItems` / `ProactiveItems` 的状态 (`revision` / `rememberSaveable`) 在弹窗里另起一份 | 它们只写各自的文件, 弹窗里改完与设置页读的是同一份; 关窗时靠回执让面板重拉 |
| 「唤醒」开关在两处 (面板上那颗按钮 + 弹窗里那行) | 允许两处入口, 但只许都调 `RouterTick.setEnabled`, 弹窗里不另存状态 |
| **真机上量到的老账**: 数字项手打之后只改了内存, 关掉弹窗再打开又回到 30 (滑块"松手才落盘"那条对手打不成立) | 这一次顺手修了: NumberRow 的 onInputConfirm 里补一次 onCommit(), check-sim.mjs 加一条钉住它 —— 不修的话读数 4 永远过不去 |
| 窄屏上三颗按钮挤不下 | `.lwp-actions` 本来就是 `flex-wrap: wrap`, 挤了就换行; 真机 1080 宽实测三颗一行 |
| `SimSettingsDialog` 多出一个 `withActivity` 分支 | 已选**备选 A** (加默认参数): 设置页零改动, 不新增壳、不加键. 独立 `ActivitySettingsDialog.kt` 那版 (备选 B) 没做 |

`OverlayDialog` 在 WebView 之上是独立 Window, 与 Miuix 主题一致; 关掉时 WebView 不重绘, 靠 §5.3 那句回执
`refresh()` 救 —— 这是这一版唯一必须做对的一处.

## 11. 不做的事

- 不在 `⋯` 菜单加行 (主人 2026-11-13 明说); 也不在抽屉最底下另起一行 (第二轮改口径: 动作行最右)
- 不在网页里用 CSS 画设置卡、不新增桥方法读写 `sim.json` —— 那是第二份参数表
- 不给面板加"编辑态" (读数就地变输入框) —— 面板是读数页, 改值一律走弹窗
- 不改面板上任何一行读数, 不动 `checks` 的「已处理」那条路
- 不在弹窗里放「记着的事」、任务卡编辑、摘要跳转
- 不为这个功能新建 `ActivitySections.kt` / `ActivitySettingsDialog.kt` (试过, 拆法只增加移动量)
