# Luwi 图标切换 方案 (2026-11-22)

主人三条: ① 在设置的外观里加上切换 luwi 图标的选项; ② 允许用户切换图标, 图标加上这张图, 并默认使用这张;
③ 切换时要确保所有用到图标的情况都要切换。

## 一、五类位置与各自的通路

| 位置 | 原来 | 现在 |
| :-- | :-- | :-- |
| 桌面图标 / `roundIcon` / 启动闪屏 / 最近任务 / 应用信息 / 分享与授权弹窗 / 组件选择器 | `MainActivity` 自带 `MAIN + LAUNCHER`, 读 `@mipmap/ic_launcher(_round)` | 两个 `activity-alias` 承载入口 (`.IconBuiltin` / `.IconMaid`), 每套自己的 `icon` + `roundIcon`; `MainActivity` 本体不再带 LAUNCHER |
| 球的空闲标记 | 固定 `R.drawable.ic_launcher_foreground`, 染白 | `IconSet.markRes` / `markInkRatio` / `markTintWhite`, 尺寸按 `IconTheme.boxDpForInk` |
| 开屏缺省图 | 固定矢量 112dp | 当前套的 `markBitmap`, 盒子按墨迹换算 (`splash.json` 的 `icon` 仍优先) |
| 桌面组件缺省立绘 | 固定矢量 | `IconTheme.markRes(context)` |
| 门户缺省头像 (含终端页) | 页面内嵌 `MARK_PNG` (由 `make-portal-mark.py` 生成) | `portalLook` 多交 `mark` / `markVer`, 页面缓存后画; `MARK_PNG` 降为最后兜底 |
| 通知 small icon ×5 | `R.drawable.ic_notification` | `IconTheme.notificationIcon(context)` (每套一张单色白模) |

系统级那几处 (启动闪屏 / 最近任务 / 应用信息 / 分享弹窗) 读的是 PackageManager 里的 application icon,
alias 一换它们自动跟随, 不加代码。

## 二、桌面为什么只能是 alias

启动器读的是 APK 里的资源, 系统没有"应用运行时替换自己 launcher icon"的 API。所以每套图标必须在构建期
就有一份资源 + 一个 alias, 切换 = `setComponentEnabledSetting`:

- **先启用目标、再停旧的** (`IconSet.switchPlan` 的顺序): 反过来那一瞬间桌面上零入口, 部分 ROM 会就此
  把图标清掉
- **`MainActivity` 本体不许留 LAUNCHER**: 留着就是同一个应用两个桌面入口
- 切完要回读 `getComponentEnabledSetting` / `ActivityInfo.enabled` 校验; 失败就把原来那套恢复并回滚
  `lw/icon.json`
- 冷启动 `IconTheme.sync` 对一次账: `icon.json` 是权威, PackageManager 的状态可能被桌面 / ROM 改过
  (最坏两套都停用 = 桌面上一个入口都没有); 没有不一致时它一个字节都不写, 免得每次冷启动都让桌面重绘

代价 (必须在界面上说): alias 是另一个 ComponentName, 桌面会把它当"另一个应用"重新摆放 —— 图标可能挪屏、
被踢出文件夹; 小米系有图标缓存, 有时要等桌面自己刷新。设置对话框底部那行小字写的就是这件事。

## 三、素材与换算

`tools/make-icon-sets.py` (吃 RGBA 插画, 与 `make-icons.py` 共用渐变 / 密度档 / 通知内缩三个常量):

- `ic_mark_<id>.png` —— 透明底、内容占 0.96 的方形画布, 给应用内四处用 (`markInkRatio = 1.0`)
- `ic_launcher_<id>(_round).webp` ×5 档 —— 渐变打底 + 内容占 0.62 (keyline 安全区)
- `ic_launcher_<id>_foreground.webp` ×5 档 + `mipmap-anydpi/ic_launcher_<id>.xml` —— 自适应图标, 背景复用
  内置那份 `ic_launcher_background`
- `ic_launcher_<id>_mono.png` / `ic_notification_<id>.png` —— alpha 白模

尺寸换算: `boxDpForInk(inkDp, set) = inkDp / set.markInkRatio`。内置那份矢量墨迹只占 0.46 (唯一一个不许动的
数), 女仆那张是紧裁过的满幅 (1.0)。球那一档 `ballDrawDp * 0.65 / 0.46` 与旧算式逐字节相同 (`IconSetTest`
钉着), 开屏两份看起来一样大。

## 四、落盘与默认

- `$DSH_HOME/lw/icon.json` = `{"v":1,"set":"maid"}`; 应用单写 (与 `PortalFace` / `SimSetting` 同一条分工)
- 缺文件 / 坏 JSON / 认不出的值一律回 `IconSet.DEFAULT = MAID` (主人点名"默认使用这张")
- manifest 里 `.IconMaid` 初始 `enabled="true"`, `.IconBuiltin` 初始 `enabled="false"`; 老机器升级后
  桌面旧图标 (component = `MainActivity`) 会消失, 新图标出现在 alias 的位置 —— 这是 alias 方案的固有迁移

## 五、判据

- `IconSetTest` —— 缺省、坏值兜底、`switchPlan` 的顺序 (先开后停 / 不含目标自己)、`0.46` 那一档的回归
- `tools/check-icon-sets.mjs` (58 条) —— 清单两个 alias 的 `targetActivity` / icon / roundIcon / LAUNCHER /
  初始 enable 状态, `MainActivity` 无 LAUNCHER 且仍 `singleTop`; 两套资源齐全; 缺省 = MAID; 五类位置都接
  `IconTheme`; 5 处通知不再写死资源; 生成脚本的产物名对齐
- `tools/check-luwi-portal.mjs` 第二十九节 —— `mark` / `markVer` / `MARK_CACHE` / 终端页也吃当前套

## 七、踩到并修掉的一条 (2026-11-22)

`BallView.show()` 里判 stamp 不够: `OverlayService.refresh()` 才是决定"要不要叫 BallView 一趟"的地方
(它的条件是 `force || changed || ring != lastRing || rethemed`)。只把判据写进 `show()` 时, 主人切了图标
球纹丝不动 —— 真机现场。现在 `refresh()` 里多一档 `restyled = IconTheme.stamp(this) != lastIconStamp`,
`check-icon-sets` 钉住这一条。
