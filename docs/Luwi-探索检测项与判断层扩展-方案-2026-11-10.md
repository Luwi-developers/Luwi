# 探索检测项与判断层扩展 方案 (2026-11-10)

## 0. 一句话

让"探索交上来的检测项"这件事从**允许**变成**会发生**（文案收紧 + 空手留痕 + 卡片提醒），
再给判断层补上它唯一缺的两样输入：**日历**与**事件型判法**；顺带把 stickers 那条断掉的
"自己攒表情"接上（下载 → 落盘 → 引用），并把它补进主动场 B 表。

## 1. 背景与现状读数 (2026-11-10)

## 3. C · persona 措辞收紧

### 3.1 改法

`presets/explore/cordis.patch.yml` 第 19 条 (c) 整段替换：

```
(c) checks: 收尾时至少交一条你最有把握的"接下来该盯着什么"，最多 3 条，每条一句人话加一种判法。
    判法有三种: usage (某个应用今天满多少分钟) / time (每天几点之后, at 之前不判) /
    event (日历里的事件开始前 N 分钟, 例如出门前 30 分钟)。
    只写你有证据的 (哪一屏看见的、哪份摘要写过)，临时状态 (电量、当前页面) 不写。
    **实在没有值得盯的规律，就在摘要"仍不确定的点"里写明这一趟为什么没有 —— 不要空着不说，
    也不要为凑数编。**
```

三处语义变化：

1. `这一趟看出……的`（条件句）→ `至少交一条`（默认动作）；
2. 新增"没有也要写理由"，且理由落在摘要的**固定节**（`仍不确定的点`）—— 于是"沉默"与"想过但没找到"
   在盘上变成两种不同的东西，读数是可数的；
3. 判法从两种变三种（D 落地后才成立，C 可以与 D 同批，也可以先按两种写、D 那一批再改这一句）。

### 3.2 判据

`tools/check-explore.mjs` 现在断言 `needed('这一趟没看出新的就不交')`，
改成两条：`needed('至少交一条你最有把握的')` + `needed('为什么没有')`。
旧断言必须同步改掉，否则那一条会红（属预期红，改写时一起换）。

## 4. A · 任务卡 + 开场正文补那一句

### 4.1 先纠正一个坑

`exploreTaskWrite` 写卡时只落 `${body}\n`，而 `body` 是模型这次交的 `nextTask`。
**所以手改 `explore-card.md` 只在下一场有效，那一场收尾后就被整份覆盖** ——
"改这张卡，改了下一场就生效"这句话只在第一场成立，之后靠不住。

### 4.2 改法：两处，一处扛覆盖

| 位置 | 改什么 | 为什么 |
| :-- | :-- | :-- |
| `exploreTaskWrite` | 写入时拼一段**宿主固定尾注** `EXPLORE_CARD_TAIL`（不来自模型）：`## 收尾三样` + 三行（nextTask / 至多 3 条 checks / 没有就写明为什么） | 每次覆盖都带上，主人手改也改得掉（他删了就是删了，宿主下次再补回去；这是"主人关掉的不会被偷偷打开"的同一条纪律） |
| `exploreStartLine` | 正文里加一行：`收尾: nextTask + 至多 3 条 checks (没有就写明为什么)` | 这是模型**每场必读**的那段，且永远不会被覆盖 |
| `explore-card.md`（数据） | 收尾那一节加同一句人话 | 立刻生效、可手改、设置页看得见 |

三处一句话不重复措辞：卡里是"给自己的作业"，正文里是"硬提醒"，persona 里是"规矩"。

### 4.3 判据

- `check-explore.mjs`：`needed('收尾三样')`、`needed('至多 3 条')`；且断言 `exploreTaskWrite` 里出现
  `EXPLORE_CARD_TAIL`（防止"只改数据文件、宿主那条被谁删了"静默失效）；
- 真机：手改卡 → 跑一场 → 收尾后 `cat` 卡，尾注还在；把尾注手删 → 下一场收尾后回来。

## 5. B · 空手也留痕

### 5.1 落点

`finishExplore` 里两处 `await exploreChecksWrite(askedChecks)`（正常收尾那条、`already` 补交那条）
收成一处 helper：

```
exploreRecordChecks(checks) -> 写 explore.json
  lastFinish: { at, ended, written, total }
  checksStreak: written > 0 ? 0 : (上一笔 + 1)
```

规则：
- `written > 0` → `checksStreak = 0`；
- `written === 0` → `checksStreak += 1`（连着的场数，用来回答"是偶尔没交，还是她根本没在想"）；
- 只改自己的键（合并式原子写，与 `exploreStateWrite` 现有写法一致），不动 `run` / `screens`。

### 5.2 应用侧读数

`ExploreOverview()`（`ui/SettingsScreen.kt` 3445）在预算那一行下面加一行：

```
检测项: 共 4 条 · 上一场交 0 条 (11-09 03:12) · 已连续 2 场没交
```

读的是 `explore.json` 的 `lastFinish` / `checksStreak` 与 `RouterChecks.count()`；
`ExploreStatus.Snapshot` 加两个字段（`checksWritten` / `checksStreak`），字符串中英各两条。

### 5.3 判据

- 单测（与现有 `ExploreStatusTest` 同风格）：`exploreState` 解析、streak 递增与归零；
- 真机：连跑两场都不交 → 设置页显示"已连续 2 场没交"；交一条 → 归零。

## 6. E · 日历接进判断层输入（D 的前置）

### 6.1 数据从哪来

宿主有桥：`lw_calendar` 就是 `call('calendar', {op:'events', from, to, limit})`，
应用侧走 `CalendarContract`（自动指令的 `calendarSoon` 用它，说明权限路径已通）。
**不新造文件**：判断层每次 tick 直接问一次桥，好过再加一个"谁写、谁读、什么时候过期"的账。

### 6.2 改法

`readRouterInputs` 里加一段：

```
calendar = await readCalendarWindow(now)
  窗口: now - 60min ~ now + 24h, limit 200 (与 lw_calendar 同一上限)
  桥调用包 1.5s 超时; 成功 -> { available: true, at, events: [{id,title,startMs,endMs,allDay,calendarId}] }
  失败 / 无日历权限 / 超时 -> { available: false, why }  (fail-open: 这一拍 event 类不命中, 记一行)
  内存缓存 60s (给"准点那一拍"连发用; 一拍一次本来就不需要缓存)
```

`judgeRouter` 保持纯函数：`input.calendar` 由 `readRouterInputs` 灌进去，
`check-router.mjs` 抽源码跑的那一段（`const ROUTER_DEFAULTS` ~ `function ballReplyPolicy`）里
**只允许出现纯逻辑** —— 新的 event 命中函数必须落在这一段之内，否则判据抽不到。

### 6.3 准点那一拍（不做这个，"前 30 分钟"会抖 ±25 分钟）

判断层算出一个 event 候选时，把"下一次值得看的时刻"写进 `router.json` 的 `nextWakeAt`
（= min(事件开始 - beforeMinutes, 现在 + 最短间隔)）。

`RouterTick` 排下一次时（现有 `arm` 那一处）加一个可选覆盖：`nextWakeAt` 比随机间隔更近，就按它排。
没有 `nextWakeAt` 就还是 25~55 分钟的随机 —— 一拍的随机性不为这件事破掉。

### 6.4 判据

- 真机：建一个 6 分钟后的日历事件 + 一条 `beforeMinutes: 10` 的检测项 → 3 分钟内开口；
- 删掉事件 → 不开口（说明读的是真日历，不是缓存里的事实）；
- 关掉日历权限 → 不崩、不误报，`op=status` 与日志里能看到 `calendar.available: false`。

## 7. D · 第三种判法 `event`

### 7.1 形状

```
{ what: "出门前问一句带没带伞", when: { kind: "event", beforeMinutes: 30, titleContains: "上班" }, at: "06:30" }
{ what: "会开完了问一句",       when: { kind: "event", afterMinutes: 10 } }
```

| 字段 | 规则 |
| :-- | :-- |
| `beforeMinutes` | 1..1440，与 `afterMinutes` 二选一；都不给 = 15 |
| `afterMinutes` | 1..240（第一轮先只做 `beforeMinutes`，`after` 留作扩展位，见 §10） |
| `titleContains` | ≤ 20 字，不区分大小写；缺省 = 不筛标题 |
| `calendarIds` | ≤ 5 个；缺省 = 所有日历 |
| `at` | 仍是**下界**（HH:mm），与现有两种判法同一语义 |

### 7.2 命中

- `beforeMinutes`：存在事件，`0 < startMs - now <= beforeMinutes`，且标题匹配 → `fact` =
  `「周会」10:30 开始, 还有 12 分钟`；
- 全天事件（`allDay`）不参与 `beforeMinutes`（"今天生日"不是"30 分钟后开始"），
  它该走 `time` 判法；
- `calendar.available === false` → 这一条不命中，**不猜**。

### 7.3 去重键（这一处不改，会议提醒只会响一次）

现在 `checksSaid[id]` 存的是 `YYYY-MM-DD`，对 usage / time 是对的，对 event 是错的：
同一场周会下周还开，`id` 一样，会被"今天提过了"永久挡住。

改法：

- `routerCheckHit` 返回值由 `string` 变 `{ fact, key }`；
  - usage / time → `key = routerDayKey(now)`
  - event → `key = `${routerDayKey(now)}@${startMs}``（每一次发生一个键）
- `judgeRouter` 比较 `checksSaid[id] === key`；`routerMarkSaid` 照旧写 `key`。

副作用：`check-router.mjs` 里现有的 `routerCheckHit` 断言是字符串比较，改形状会红 ——
属预期红，同一批里把断言改成取 `.fact`。

### 7.4 校验（宿主，`exploreChecksWrite`）

白名单从 `usage / time` 扩到 `usage / time / event`；event 那一支要校验
`beforeMinutes` 是 1..1440 的整数、`titleContains` ≤ 20 字、`calendarIds` 是 ≤ 5 个字符串。
**参数坏的整条丢掉**（沿用现规），不写一半 —— 判断层里一条算不出来的检查项等于每拍白算一次。

### 7.5 展示与说明

| 面 | 改什么 |
| :-- | :-- |
| `RouterChecks.kt` 的 `how` | 加一支：`日历事件前 30 分钟 · 含「上班」` |
| 设置页那条清单 | 不用改结构（`how` 直接显示），但空态文案要从"还没有检测项"改成"探索还没交过检测项（每天她自己会加）" |
| `lw_explore` 的 `checks` 参数说明 | 加第三个形状的例子；"Two shapes" → "Three shapes" |
| `lw_calendar` 说明 | 不用改（它是读日历的工具，不是判据） |

### 7.6 判据

`check-router.mjs` 新增真值表（都跑上线源码）：

| 用例 | 期望 |
| :-- | :-- |
| 事件 12 分钟后、`beforeMinutes: 30` | 命中，`fact` 含标题与"12 分钟" |
| 事件 45 分钟后、`beforeMinutes: 30` | 不命中 |
| 事件已开始（`startMs < now`） | 不命中 |
| 全天事件 | 不命中 |
| `titleContains` 不匹配 | 不命中 |
| `calendar.available === false` | 不命中，且不抛 |
| 同一事件第二次 tick | `checksSaid` 命中同一 `key` → 不重复说 |
| 同一场会议**下一天** | `key` 变了 → 可以说 |

`check-explore.mjs` 新增：`exploreChecksWrite` 收 event 形状、拒坏参数、`titleContains` 超长被拒。

## 8. F · stickers 的下载 → 落盘 → 引用

### 8.1 现状为什么是断的

- `lw_sticker` 只 `list` / `say`，读 `$DSH_HOME/lw/stickers`；
- `lw_download` 走系统 `DownloadManager`，落的是**共享 Downloads**，拿不到 app 私有目录；
- 于是"她自己攒表情"这条链现在缺中间一段：**没有一条把网络图片放进 stickers 目录的路**。

### 8.2 改法：给 `lw_sticker` 加 `op=fetch`

| 项 | 规则 |
| :-- | :-- |
| 入参 | `url`（必填）、`name`（可选，缺省取 URL 的 basename） |
| 协议 | 只收 `https`；GET，8 s 超时 |
| 体积 | ≤ 2 MB（与 `list` 那道同一上限） |
| 类型 | 按**魔数**判 png / jpg / gif / webp，扩展名以魔数为准，不信 URL 后缀 |
| 名字 | 去扩展名后限 `[\w\u4e00-\u9fa5-]{1,24}`，非法字符一律拒（与 `lw_say` 那条"带路径的名字不认"同一纪律） |
| 落点 | `$DSH_HOME/lw/stickers/<name>.<ext>`，`.tmp` + rename 原子写 |
| 同名 | 覆盖（"换一张"就是覆盖；`lw_say` 的引用语义本来就按文件名） |
| 回执 | 只说"存下了 N 张，op=list 可看"，**不自动贴** —— 贴不贴由 `lw_say` 决定 |
| 上限 | 目录 200 张 / 总 40 MB，超了拒并列出最旧 5 张让人删 |

### 8.3 必须补进 B 表（否则是一条绕过闸的路）

`lw_sticker` 现在不在三张表里 —— 表外 = 三档都放行。而 `op=fetch` 会**外发网络请求并落盘**，
所以 `PROACTIVE_ACT_TABLE` 加一条：

```
['lw_sticker', new Set(['list', 'say'])]   // fetch 属写动: act / full 才放
```

同一条纪律（"新加的会动设备的工具必须补表"）已经在 `Luwi/AGENTS.md` 里，落这一条时把
`lw_sticker fetch` 写进那一句的邻近位置。

### 8.4 判据

- 单测：魔数判别（伪造 `.png` 后缀的 jpeg）、超 2 MB 拒、非法名字拒、同名覆盖、目录上限；
- 真机：`remind` 档 `op=fetch` 拒且回执说清；`act` 档成功后 `op=list` 看见、
  `lw_say {sticker:"开心"}` 贴出去门户与球**同一张**（一处写两处显示那条不变量）。

## 10. 风险与回退

| 风险 | 处置 |
| :-- | :-- |
| `checksSaid` 形状改了，旧账读不出来 | 旧值是 `YYYY-MM-DD` 纯日期，新值多一个 `@...`；读侧按"字符串不等就是不等于"处理，等价于"这次没说过"，只会多提醒一次，不会永久静默 |
| event 检查项在没日历权限的机器上永远不命中 | `calendar.available: false` 要能被看见：`lw_explore op=status` 与设置页探索段各一行；探索摘要的"风险与拦截记录"里要求写明 |
| 准点闹钟把 tick 变密 → 更耗电 | `nextWakeAt` 只在"有 event 检查项且窗口在 2 小时内"才写；一天最多几次 |
| `lw_sticker fetch` 成了一条外带通道 | 只出站、只 GET、只收图、≤2 MB、落点固定、名字受限、进 B 表、每次写一行日志 |
| 主人手改任务卡又被覆盖 | 尾注由宿主拼；他删了尾注宿主会补回来 —— 若他真的不想要，正确做法是关掉那条检查项（设置页可关），不是删卡 |

回退：A/B/C 都是文案与读数，删掉即恢复；D 的 `event` 白名单去掉 → 那些检查项被"坏参数"规则丢掉；
E 的桥调用包在 try 里，删掉那一段 `judgeRouter` 照旧跑；F 的 `op=fetch` 分支删掉即恢复原状（B 表那一条一起删）。

## 11. 待定（要主人拍）

1. **`afterMinutes` 要不要这一批就做**：建议只做 `beforeMinutes`，`after` 留第二轮 —— 两个窗口同时给的语义
   （"两个都算"还是"算一个"）值得单独一次拍板。
2. **`weekdays`**：`time` 现在也不支持"只在工作日"，`event` 会继承这个缺陷。建议另开一条账，
   两种判法同时加，别只给 event 加。
3. **空手连续几场要提示**：设置页那行 `已连续 2 场没交` 是只显示，还是超过 3 场就发一条提醒？建议只显示。
