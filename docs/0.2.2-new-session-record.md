## 闸一: 没有 android 侧的写租约绑定 (已修, 落在打包那一步)

```
新建会话失败: gateway/internal: failed to create session:
Error: flock is not supported on android-arm64
```

`@deepseek-ai/dsh-session-persistence-jsonl/src/lease.ts` 在 POSIX 上必须先用
`tryLockExclusive(handle.fd)` 拿写租约; 而 `@deepseek-ai/node-addon-system` 只认 `linux` / `darwin`,
`loadBinding()` 见到 `android` 直接抛 `ERR_FLOCK_UNSUPPORTED_PLATFORM`。树里也没有任何
`node-addon-system-<platform>-<arch>` 平台包, 所以这条路在安卓上本来就走不通。

**修法**: `tools/pack-host.mjs` 末尾 (node-pty 那一步之后) 给物化出来的
`node_modules/@deepseek-ai/node-addon-system/lib/flock.js` 插一条安卓直通
(`tryLockExclusive` 里 `if (process.platform === 'android') return`)。理由是宿主**单进程**,
进程内写占用已经互斥 —— 与上游 `webworker-runtime` 那份单进程替身
(`node-addon-system-flock.ts`) 同一个理由。

**没有改 fork 源码**: `native/system/AGENTS.md` 写着"缺绑定时拒绝获取, 绝不静默放行", 那是上游对
多进程 POSIX 的契约; 这一条是 Luwi 对自己这个单进程宿主的决定, 所以只在打包这一步做, 上游发了
android 预编译 (或者持久化那层给出显式的单写者模式) 就把那一段删掉。

## 闸二: 组成里有一条 0.2.2 已经不发的旧行 (已修, 三份 preset)

补掉闸一之后立刻换个错法:

```
新建会话失败: agent-preset/invalid: tool-subagent-list-agents
(@deepseek-ai/dsh-tool-subagent-control/list-agents): never started
```

`agent-preset-registry/src/mount.ts` 的 `auditRows` 把"没拿到 fiber 的行"报成 `never started`。
那一行的包名是 `@deepseek-ai/dsh-tool-subagent-control/list-agents`, 而那包的 `exports` 只有
`.` / `./src/*` / `./package.json` / `./locale/*.json` —— **没有 `./list-agents`**; `lib/` 下也只有
`index.js` 与 `types`。0.2.2 把 `list-agents` 并进了主模块 (`apply` 里直接 `registerListAgents`),
独立那一行是 0.2.1 的写法。

**修法**: 三份组成里删掉那两行 —— `presets/luwi/cordis.patch.yml`、
`presets/explore/cordis.patch.yml`、`presets/custom-mode/package/preset/agent.cordis.yml`。
(`tool-subagent-control` 这一行照留: 它自己就注册 `list_agents` 与 `send_message`。)

**顺手排掉的虚假修法**: 先试过往 `delegation` 组里补 `subagent` / `subagent-spawn-in-process` /
`subagent-fork-in-process` 三行 (上游 `dsh-base` 的 `standard` 组成里有这三行), 结果连着报
`service "subagents" has been registered at <SubagentRuntime>` 与
`a subagent provider named "spawn" is already registered` —— 那三样在 Luwi 这条 profile 上已经由
别处提供, 组成里再写一遍就是重复注册。**这两次读数本身是有价值的**: 它们证明 `subagents` 不缺,
缺的只是那条已经不存在的行。

## 另一处 0.2.2 的平台差: 左侧抽屉打开是一块白 (同日修)

症状 (主人 2026-11-08): 左侧边栏打开是白的; 有时打开也会立刻弹回去。

根因还是 `dsh-web-mobile` 那条按 `[data-mobile-nav="frame"] > :first-child` 写的抽屉规则
(它假定框架第一个孩子就是侧栏列)。0.2.2 起框架的孩子顺序是
`drawerMask, sidebarCol, centerCol, rightbarCol, bottomRow, overlayLayer, leadingSeat` ——
第一个是**遮罩**, 于是:

- 遮罩被当成抽屉列: 收起时推到 -110% 屏外, 打开时 `transform: none` 把一块 280px 宽、
  `--dsw-specific-sidebar-fill` 底、z 1300 的**空**遮罩滑上屏, 正好压在真侧栏 (宿主 z 71) 上
  —— 看到的就是"白";
- 同一块遮罩又是宿主的"点一下关闭"背面, 于是抬手的那一下 (或者紧接着的一次点击) 把抽屉关掉
  —— "有时一开就弹回";
- 就算把遮罩还原, 插件自己的变暗背面在 z 1250, 而它那条"列 1300"落到遮罩上了: 宿主的侧栏列只有
  z 71, 于是背面仍压在抽屉上, 抽屉发灰发白。

修法 (`presets/ui-fix/lib/client.js` 第四节, 判据 `tools/check-ui-fix.mjs`):

```css
@media (max-width: 1023px) and (pointer: coarse) {
  html body #root [data-mobile-nav="frame"] > [data-sidebar-mask] {
    position: absolute !important;
    inset: var(--dsh-frame-chrome-top, 0px) 0 0 !important;
    width: auto !important; max-width: none !important;
    z-index: 70 !important; transform: none !important;
    padding-top: 0 !important; border-right: 0 !important;
    background: var(--dsw-alias-bg-mask-1) !important;
    pointer-events: none !important;
  }
  html body #root [data-mobile-nav="frame"] [class*="sidebarCol"] { z-index: 1300 !important; }
}
```
