# Luwi 朗读与显示分离 方案 (2026-11-09)

## 0. 一句话

数据流不拆: **显示流**(jsonl, 门户与球同源) 一个字节都不动, 只把**朗读流**从"逐行跟读"改成
"自己一段稿子 + 自己的游标", 并允许念的稿子与显示的那句不同 —— **缺省仍然相同**。

## 1. 问题

### 1.1 现象

主人在门户发消息后, 门户与球显示的内容偶有出入 (球多一句"嗯"、一句收尾话之类), 且朗读只能
逐行跟着气泡念, 长句与符号都被原样念出来, 听感差。

### 1.2 根因 (2026-11-09 代码读数)

两边不是同一套渲染器, 重叠的只有 `lw_say` 写的那一份 jsonl:

| | 门户 (`presets/luwi-portal/lib/client.js`) | 球 (`overlay/OverlayService.kt`) |
| :-- | :-- | :-- |
| 取数 | ChatSnapshot 的 **user 节点** + jsonl 里**已放出**的行 (`releasedIds`), 第 901 行注释写明 assistant 不取 | jsonl 增量 (`OutFile.page`, 水位 `outWatermark`) |
| 正文 | 只在本轮**一条 lw_say 都没有**时兜底画 assistant 最后一句 (1597-1631) | `op=reply` 推整轮"该说给人听的那一句" (仅 preset 不在 `BALL_SILENT_PRESETS` 时) |
| 其它 | 无 | `op=note` (⚠)、`op=say` (判断层那句) |
| 取行时机 | 3 s 轮询 (`call('portalOut', …)`) | `FileObserver` 事件驱动 |
| 撤队 | 新 user 节点 → `clearOut()`, 而水位在取到时已推到最后一行 (1452) → **未放出的行永久丢** | 仅在 `ask` (新一轮真排上) 清队 |

`BALL_SILENT_PRESETS = new Set(['explore', 'luwi'])` (`host-plugin/index.mjs` 7587)。
本机当前那一场 `session-99a620a7…` 的 `agentPreset` 是 `luwi`, 所以 `op=reply` 不该发生 ——
球上多出来的那句更可能来自 jsonl 放出时点差, 或门户撤队丢行。

### 1.3 为什么不能靠"让 agent 写两套文案"解决

两套 = 双倍 token + 两份必然漂移。而"文字一致"恰恰是这次要保住的东西。第二稿必须优先由
**规则**生成, 模型只在真的换说法时出手 (§4.3)。

## 2. 现状链路 (读数)

```
lw_say (host-plugin/index.mjs 4509)
  └─ lwOutAppend → $DSH_HOME/lw/out/<sessionId>.jsonl
       行: {seq, at, gapMs, roll, kind: text|image|file|sticker, text, rel, …}
       ├─ 门户 PortalBridge.portalOut(id, next) → OutFile 解析 → 气泡 (按 releasedIds 放)
       └─ 球  OutFile + OutWatch → outbox → drainOutbox (按 gapMs / dueAt 放)

朗读 (与上面完全独立的一条):
  lw_say({speak:true}) / 一轮 turn/end 的 startReadAloud (9351)
    → readAloudText 洗 markdown (6820)
    → call('speak', {op:'clip'}) 先垫预录音 (padClipFor, 20 字以下不垫 / 80 字以上垫 thinking)
    → call('speak', {op:'speak', text}) → LwSpeak → LwEdgeTts (联网合成) → 播放
```

要点: `op=speak` 收的是**任意字符串**, 从不校验它是否等于某个气泡 —— 分离的底子已经在了,
缺的只是"输入可以不是那一行"和"念到哪的账"。

## 3. 目标与非目标

**目标**

1. 文字一致性不回退: 显示流仍是"一份 jsonl + 一份解析器 + 一份 gapMs"。
2. 朗读可独立成型: 一次调用合成**一段**, 而不是逐行; 去符号、去括号、跳过文件条目。
3. 缺省行为与今天完全一致 (念的就是显示那句), 不引入新的配置负担。
4. 打断有明确口径: 当前段念完即停, 不切半句、不念过时的话。

**非目标**

- 不改 jsonl 的行格式与解析器 (只在需要时**追加**一个可选键)。
- 不让朗读影响显示节奏 (`gapMs` / `dueAt` 仍只归显示流)。
- 不引入新的 TTS 引擎; 不改填音与 `LwClips.follow` 的既有逻辑。

## 4. 设计

### 4.1 两条流

```
显示流: jsonl ──→ 门户 / 球 (逐行, 按 gapMs)          ── 永不等合成
朗读流: 朗读稿 ──→ 合成 (可预取) ──→ 播放队列 ──→ 游标  ── 只读显示流, 不写它
```

硬口径: **显示流永不等合成**。文字上屏路径 (球 FileObserver 立即 / 门户 ≤3 s 轮询) 与
Edge 合成没有依赖关系; 如果哪天实现成"合成完才显示", 那就是本次改动引入的延迟, 直接判红。

### 4.2 数据契约

jsonl 行**不改**。`lw_say` 增加一个可选参数 `voice` (字符串, ≤600 字), 只在"念法与说法不同"
时给; 不给就念 `text` (或 `lines` 拼起来那一份)。

| 情况 | 显示 | 朗读 |
| :-- | :-- | :-- |
| 只给 `text` | text | 规则洗过的 text (§4.3 第 2 级) |
| `speak: true` | text | 同上 (显式要求出声) |
| 给 `voice` | text | 规则洗过的 voice (第 3 级) |

`voice` 不写进 jsonl 的显示字段, 由宿主单独交给朗读流; 若需要复跑, 记在
`$DSH_HOME/lw/read/<sessionId>.jsonl` (§4.4) 而不是污染显示流。

### 4.3 朗读稿生成 (三级, 由便宜到贵)

1. **原样**: 已经是纯口语 (短句、无符号) → 直接用, 零处理。
2. **规则洗** (默认, 宿主侧, 不花 token): 在现有 `readAloudText` 上补四步
   - 去 Markdown 残留 (`**`、表格、行内 code) —— 现在已有;
   - 去括号补充 (`（…）` / `(…)` 整段丢);
   - 文件条目念成"一份文档"/"一张图", 不念文件名与扩展名;
   - 按句末标点断句, 一段最多 N 句 (缺省 6), 超过就分段合成。
3. **显式 `voice`** (模型出手): 念数字、念链接、把列表换成口语、改称呼。
   只有在第 2 级读起来会怪时才用; 用了就在宿主日志记一行
   `lw_say: the spoken line differs from the shown one (seq N)`。

### 4.4 朗读游标与账

朗读是自己的一本账, 与显示水位彻底分开:

- **内存态** (应用侧, `LwSpeak`): `{sessionId, nextSeq, speaking: Boolean, currentSeq}` —— 进程
  重启允许丢 (丢的后果只是"这一句不念", 不是"念两遍")。
- **落盘** (可选, 只给门户显示"正在念哪句"): `$DSH_HOME/lw/read/<sessionId>.json`,
  `{seq, at, state: queued|speaking|done|cancelled}`。
- 合成缓存: 应用 `cacheDir/read/` 里一份 `<sha1(text)>.mp3`, 命中就直接播 (§4.7)。

### 4.5 打断与停止

| 事件 | 显示流 | 朗读流 |
| :-- | :-- | :-- |
| 新 user turn (`ask`) | 清未放出的行 (现状) | **当前段念完即停**, 队列里未开始的丢弃 |
| 换会话 / 收起门户 | 清队 | 立即停 (与今天的 `LwClips.stop` 一致) |
| 朗读开关关掉 | 不变 | 合成照做, 播放跳过 (与现在 `readAloud === false` 一致) |

"念完当前段就停"是刻意的: 切半句在听感上比多说一句更糟。实现上空一个 `op=cancel` 只置标志,
播完当前音频再退出, 不打断正在放的文件。

### 4.6 时序

```
t0  lw_say 写 jsonl                      (毫秒)
t0  宿主同时发 op=prepare (可选)          合成开始在后台跑
t0+0~3s  文字上屏 (gapMs 1~3 s 的人为节奏)
t0+0.3~2s  合成完成, 进缓存
显示放完这一段 → 朗读放 (命中缓存 ≈ 立刻出声)
```

结论: **分开不增加延迟**。真正的延迟是 Edge 合成 (联网, 几百 ms 到几秒), 今天就有, 靠垫音
盖住; 分开之后可以预取, 把那几秒藏起来。

### 4.7 预合成与缓存

- `op=prepare` (新): 只合成不播, 落 `cacheDir/read/`; 与 `LwEdgeTts` 已有的"只合成、不播"
  能力 (给 `LwClips.follow` 用的那条) 是同一段代码。
- `op=speak` 先查缓存, 命中就直接播。
- 一次调用 (最多 6 行) 合成**一段**, 不是每行一次 —— 少 N-1 次往返。
- 缓存按 `sha1(text)` 键, 上限 20 条 / 单条 200 KB, 先进先出。

## 6. 落地步骤

**第 1 步: 稿子可以不同 (最小可验证)**

- `lw_say` 加 `voice`; 宿主 `readAloudScript` 做 §4.3 第 2 级清洗; 朗读入口改吃"这一段稿子"。
- 判据: 给 `voice` 时念的是 voice, 不给时逐字等于显示那句; 差异要落一行日志。

**第 2 步: 游标与打断**

- `LwSpeak` 加朗读队列 + 游标; `op=cancel` 支持"念完当前段即停"; `ask` 触发 cancel。
- 判据: 连续两次 `lw_say` 时, 第二轮来时第一轮未念的段落不念; 已开始的那段念完才停。

**第 3 步: 预合成与缓存**

- `op=prepare` + `cacheDir/read/` 命中; 一次调用合成一段。
- 判据: 第二次念同一句不再联网 (读数: 合成耗时 ≈ 0); 断网时静默退回"只显示不念"。

## 8. 风险与回退

| 风险 | 处置 |
| :-- | :-- |
| 文字与语音内容不一致让主人困惑 | 缺省相同; 差异必须显式 `voice` 且记日志; 只允许语气/断句/省略层的变化 |
| 朗读抢占显示节奏 | 判据钉死: 朗读流不写 jsonl、不动 `gapMs`/`dueAt` |
| 重复念 / 漏念 | 游标 + 缓存键双判; 断网时"没念"要能被下一轮补 |
| 长段落合成慢 | 一段最多 6 句, 超出分段 |

回退: `voice` 不给 = 老行为; 桥新 op 都是增量, 旧宿主遇到未知 op 直接忽略即可。

### 10.3 设备读数 (真机 A `OJZD5D6TMNSKFYHM`, 2026-11-10 01:49-01:55)

桥调用 (`speak` 那一族, 走 `127.0.0.1:<channel port>`, 媒体音量 0 = 全程静音):

| 动作 | 读数 |
| :-- | :-- |
| `op=status` (装完第一次) | `readingWith=system` / `readAloud=true` / `readCursor=0` / `readWaiting=0` / `readRuns=0` / `readCache=0` |
| `op=read` 第 1 段 (`seq=11`) | `queued=true, waiting=1, characters=8` |
| `op=read` 第 2 段 (`seq=12`) | `queued=true, waiting=1` (第一段已被工人取走) |
| `op=cancel` | `dropped=1` (未开始的那段丢掉) / `speaking=true` (**当前段念完才停**) / `cursor=11` |
| 6 s 后 `op=status` | `cursor=11` / `waiting=0` / `runs=1` / `played=0` / `dropped=1` / `speaking=false` |
| `op=speak` 同一句 (对照) | `spoken=false, waitedMs=17250, detail=still speaking after 17250ms` |
| `op=prepare` | `prepared=false, engine=system, why=only the Edge engine can be prepared ahead of time` |
| `op=cache action=status` | `entries=0, bytes=0, max=20, maxBytes=204800, path=…/cache/read` |
| `op=cache action=clear` | `removed=0` |

三条要如实记下的:

1. **游标与队列全对**: `cursor` 停在第 11 条, 第 12 条被丢 (`dropped=1`), 排队的账与显示流完全无关。
2. **`played` 在这台 ROM 上计不上**: 这台机器的系统引擎 (`com.baidu.duersdk.opensdk`) 从不回报
   `onDone`, `op=speak` 一律在预算 (`15 s + 250 ms/字` = 17.25 s) 后回 `spoken=false`。这不是这次引入的 ——
   旧代码在同一条路上也是这个数; 朗读队列照样按顺序念, 只是"念成了"那个计数拿不到。
3. **`op=prepare` 在这台机器上按设计拒绝**: 设置里选的是系统引擎, 预合成只对 Edge 成立。
   要读 Edge 那条的"第二次不再联网", 先在设置 → 朗读里切到 Edge 再跑:

```powershell
# 第二次的 ms 应当接近 0 (命中 ReadCache)
pwsh -File D:\apk\.lwtmp\lw-call.ps1 -Method speak -Params '{"op":"prepare","text":"预合成一句。"}'
```

(缓存那一段本身是纯文件逻辑, 键 / 上限 / FIFO 都能在 PC 上判, 见 §10.2。)

### 10.4 补记: 显示侧还有一处, 不在本方案范围 (2026-11-10)

主人报"ball 里发送的文本内容和对话层里显示的不一致"。复核结论: **本方案已经落地**, 但它按 §0 只拆
朗读流, 显示流仍是两套渲染器, 所以它管不到这件事。真机定位到三层原因:
