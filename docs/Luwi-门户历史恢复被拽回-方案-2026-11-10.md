# 门户历史恢复被拽回 方案 (2026-11-10)

## 0. 一句话

点历史只切了**门户的视野**, 没切两处**权威状态** —— 球的账本 (`$DSH_HOME/voice/session.json`) 与
dsh 的 mainView (`retainedBy.mainView`), 于是 3 s 之后 `pollLedger` 把界面拽回门户自动开的那张空场,
屏上就是"恢复两三秒又清空成新对话".

修法三件 (方案 B), 只动 `presets/luwi-portal/lib/client.js` 一个文件, 不碰 dsh 上游, 不碰 jsonl:

1. **B1** `follow(id, { align })` 让 dsh 的 mainView 一起过去 (治 `listUnsub` 那条通道);
2. **B2** `pollLedger` 从"状态驱动"改成"**账本被重写过才跟**" (治 3 s 定时器那条通道);
3. **B3** 三个换场入口收成 `switchTo(id, source)`, 并留一行 `switch by=` 日志 (以后一眼定责).

## 2. 根因

### 2.1 点历史这一步实际走了什么

| # | 代码 | 做了什么 | 没做什么 |
| :-- | :-- | :-- | :-- |
| 1 | `historyRow.onclick` → `pickHistory(node.id)` (`2191`, `2256-2263`) | 关窗 → `follow(id)` | **没有** `portalBind`, **没有** `ledgerHoldUntil` |
| 2 | `follow(id)` (`1288-1305`) | `adopt(id)` 成功后 `if (chatTarget !== null) return true` | **走不到** `ctx.uiWorkspace.openSession(id)` |
| 3 | `adopt(id)` (`1116-1167`) | 换 `chatTarget` → `renderFlow()` 画出历史 → `rememberSession(id)` 只写 localStorage | dsh 的 mainView 一动没动 |

对照 `newConversation()` 的 `land()` (`1345-1358`) 与 `send()` 的第一句 (`3565-3568`):
**那两处都是 `adopt + portalBind + 闸` 三件套, 只有历史这一条漏了** (历史窗是 11-10 这一轮新加的入口).

### 2.2 两处权威状态, 两个看门狗

| 通道 | 判据 | 拍子 | 目标 |
| :-- | :-- | :-- | :-- |
| `pollLedger` (`3610-3643`) | `ledger.usable === true && ledger.id !== sessionId` (`3633-3641`) | 固定 **3 s** (`4186`) | 账本那一场 (`voice/session.json` 的 `id`) |
| `mount()` 里的 `listUnsub` (`4173-4185`) | `currentSessionId() !== sessionId`, 而 `currentSessionId()` 读的是 `summary.retainedBy.mainView > 0` (`1081-1095`) | 会话表**一变**就跑 | dsh 的 mainView |

两条都指向同一场 —— 门户启动时 `autoStart()` → `newConversation()` 开的那张空场, 所以"清空"落在
"一张新对话"上, 而不是落在某场旧对话上.

### 2.3 对照组 (单变量, 已实测)

| 组 | 账本状态 | 点历史后 | 结论 |
| :-- | :-- | :-- | :-- |
| A | `at` = 13:34:54 (10 分钟窗口内, `usable=true`) | t+3.6 s **被清空** | 账本通道在拽 |
| B | `at` 就地改成 1 (过期, `usable=false`) | t+8 s **仍在历史场** | 账本通道是必要条件 |
| C | 手动把账本 `id` 指到另一场 (`99a620a7`), 不点历史 | 3 s 内**门户自己切过去** (历史窗顶部"当前"跟着变) | 账本单向牵引, 与点没点历史无关 |

> 实验期间改过设备上的 `voice/session.json`, **已还原原文** (备份 `/.lwtmp/portal-hist/ledger-backup.json`),
> 只是 `at` 已越过 10 分钟窗口, 下次宿主/门户写账时自然刷新.

## 3. 设计 (方案 B)

### 3.1 B1 · 让 mainView 也跟着走

`follow(id, options)` 加一个显式开关, **只有手动换场传**:

```
follow(id, { align: true })        // 历史 / 以后任何"人点的换场"
```

语义:

1. `adopt(id)` 照旧**先画** (0.7 s 内出内容, 这条不能退化成"等 openSession 回来再画");
2. 然后照做 `ctx.uiWorkspace.openSession(id)` —— 让 dsh 的 mainView 搬到这一场, 于是
   `listUnsub` 的 `currentSessionId()` 与 `sessionId` 对齐, 不再反拽;
3. `openSession` 抛 `sessions.retain: unknown session` (跨工作区 / 未加载) **不算失败**:
   画不画已由第 1 步保证, 只走现成的 `openBallWorkspace(id)` 把工作区切过去, 下一轮再对齐;
4. `openSession` 之后再 `adopt(id)` 一次 (同 id 命中 `adopt` 的 `same` 分支 `1121-1129`,
   不清界面), 兜住 replaceMain 期间 `chatTarget` 被换掉的可能.

**不传 `align` 的调用点 (`restore` `4131`/`4139`, `pollLedger` `3631`/`3636`) 行为一个字节不变** ——
冷启动那套 250 ms × 20 次的重试不能被这次改动搅乱.

### 3.2 B2 · 账本从"状态驱动"改"变化驱动"

现在的判据是"账本 id 跟我画的不一样就跟", 于是**任何没有重写账本的换场都会被拽回去**. 改成:

```
跟 随 条 件 = ledger.usable === true
           && ledger.id !== sessionId
           && (lastLedgerAt === 0 || ledger.at > lastLedgerAt)
```

`lastLedgerAt` / `lastLedgerId` 两个变量, 每次读完账本更新. 真值表:

| 情形 | `at` 变没变 | 跟随 | 说明 |
| :-- | :-- | :-- | :-- |
| 点历史 (不写账本) | 不变 | **否** | 这正是要的: 翻看不被拽 |
| 球说一句 (宿主 `voiceSessionBump`) | 变 | 是 | 原有的"球换场, 门户跟"一点没丢 |
| 门户开新对话 / 发第一句 (`portalBind`) | 变 | 是 | 与 `newConversation` 的三件套自洽 |
| 冷启动首次 (`lastLedgerAt === 0`) | — | 是 (一次) | 保住"打开就看刚聊过那场" |
| 同一场继续说 | 变, 但 `id` 相同 | 否 | 已经在这场, 不必重画 |

`ledgerHoldUntil` 那 15 s 闸**保留**, 但职责单一化: 只兜 `newConversation` 写完账本到下一拍之间的异步窗口,
不再兼职"防止点历史被拽".

### 3.3 B3 · 换场入口收敛 + 一行日志

三个入口现在各写各的. 收成一个:

```
switchTo(id, source)      // source: 'history' | 'new' | 'ledger' | 'list' | 'restore'
```

| source | adopt | openSession (`align`) | portalBind | 备注 |
| :-- | :-- | :-- | :-- | :-- |
| `history` | ✓ | ✓ | ✗ | 翻看不接管账本; 真说话时 `send()` 自己会接管 |
| `new` | ✓ | ✓ | ✓ | 就是现在的 `land()` |
| `ledger` | ✓ | ✗ | ✗ | 只画, 不反向改 dsh |
| `list` | ✓ | ✗ | ✗ | 只画 |
| `restore` | ✓ | ✗ | ✗ | 挂载时那套重试不变 |

每次切换打一行 (成本零, 价值极高 —— 这次排查就卡在"不知道谁拽的"):

```
[luwi-portal] switch by=history id=session-70433be3-12dc-46d4-aa10-692784d547fd
```

### 3.4 明确不做

- **点历史不写账本**. 写 `portalBind` 会把球接下来 10 分钟的话引到一场"只是翻看"的历史里,
  副作用比这个 bug 更烦人. 真要接管, 在那一场发一句话就够了 (`send()` 里那条 `portalBind` 还在);
- 不改 `historyRows(snapshot, query, currentId)` 的排序与置顶;
- 不改 dsh 的 `ui-workspace` / `ui-conversation`, 不改 `voice/session.json` 的格式与 10 分钟口径.

## 6. 风险与回滚

| 项 | 说明 |
| :-- | :-- |
| 唯一风险点 | `openSession` 在 `adopt` 之后调, dsh 会 `replaceMain` → ui-chat 重新 bind, `chatTarget` 可能被换掉 → 短暂空态. 缓解: `openSession` 后再 `adopt` 一次 (命中 `same` 分支); 验收第 4 条专门验它 |
| 不碰 | `adopt` 的 `same` 分支, `restore` 的 250 ms × 20 重试, `historyRows`, dsh 上游 |
| 回滚 | 单文件 revert (`presets/luwi-portal/lib/client.js`); 改完走 `pack-host.mjs` → `push-host.mjs` → 重启 host (或 `dev.ps1 install`), 判据是 logcat 出现新的 `switch by=` 一行 |
| 改动量 | 约 50-60 行 (含注释) + 判据约 30 行 |
