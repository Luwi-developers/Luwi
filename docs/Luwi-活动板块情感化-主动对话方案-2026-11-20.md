# 活动板块情感化 · 主动对话方案

> 目标: 让"活动"这一摊 (主动对话 / 主动程度 / 开口节奏 / 判断层 / 表情) 从**参数面板**变成**人格状态机**,
> 让主动开口的那一句话有"她此刻的状态 + 她记得的关系 + 这一场该用哪种陪法"三样东西撑着, 而不是一段固定的语气条
>
> 立场: 不是让模型"更会说话", 是让它在**时间维度上可预期** —— 人格是慢变量, 对话是快变量, 边界是常量
>
> 写于 2026-11-20 · 只按这一天的代码读数写, 涉及行号以当天 `host-plugin/index.mjs` (816466 字节) 为准

---

## 0. 一句话结论

当前活动板块缺的不是"情感文案", 是**三个缺失的变量**:

| 缺的东西 | 现在是什么 | 应该是什么 |
| :-- | :-- | :-- |
| 她此刻的状态 | 无。每一场从零开始 | 一个 4 维状态向量, 由文件推出来 (确定性内核, 不调 LLM) |
| 她与他的关系 | 无。只有 20 条快照 + 探索摘要 + 愿望单 | 三层关系记忆 (情节 / 画像 / 关系阶段), 带时间衰减地召回 |
| 这一场该怎么陪 | 一句语气条 (柔和 / 不催 / 不哄) | 一种**共情策略**, 由状态与关系决定, 按场景换分布 |

补上这三样, 活动板块就同时解决了三个真问题: 人格断层 (主动场与对话场不是同一个人)、
主动场健忘 (每场失忆)、无条件共情 (不会收尾, 边界失能)。

## 5. L2 情感状态: 确定性内核 (P0)

### 5.1 为什么不交给 LLM 推

LLM 每一轮"回忆自己什么心情"必然漂移, 且贵。MATE 的做法值得抄: 状态更新是**纯函数**, 输入是
状态与事件, 输出是新状态, 全程不调模型。她能感知到的只是最后那一个压缩向量。

### 5.2 四个维度

| 维度 | 取值 | 从哪来 |
| :-- | :-- | :-- |
| `valence` | -2 .. 2 | 他今天说话的密度、是否带情绪词、是否被骂过、是否有人接 |
| `arousal` | 0 .. 3 | 时段 (凌晨 / 白天 / 深夜) + 前台应用 (游戏 / 视频 / 社交) + 是否有通话 |
| `engagement` | 0 .. 3 | 24 h 内互动轮数、上次对话距今、她上次开口有没有被接 |
| `phase` | `morning` / `day` / `evening` / `late` | 本地时钟 |

### 5.3 新增模块 `host-plugin/emotion/state.mjs` (纯函数, 可判据真跑)

```js
/** 基线: 她自己的情绪不是 0, 而是一点点偏暖 (主人 2026-11-19: 语气柔和客气) */
export const AFFECT_BASELINE = Object.freeze({ valence: 1, arousal: 1, engagement: 1 })

/** 半个衰减: 一天不互动, 状态往基线回一半 —— 这就是"睡一觉起来气消了" */
const HALF_LIFE_MS = 12 * 60 * 60 * 1000

/** (state, event) → newState. 纯函数, 无 fs 无时钟: 调用方把 now 放进 event */
export function affectStep(state, event) {
  const at = Number(event?.at ?? 0) || 0
  const prev = {...AFFECT_BASELINE, ...(state ?? {})}
  const cold = decayTowards(prev, at, event?.now ?? at)
  const kind = String(event?.kind ?? '')
  const delta = AFFECT_DELTAS[kind] ?? {}
  return {
    valence: clamp(cold.valence + (delta.valence ?? 0), -2, 2),
    arousal: clamp(cold.arousal + (delta.arousal ?? 0), 0, 3),
    engagement: clamp(cold.engagement + (delta.engagement ?? 0), 0, 3),
    at: event?.now ?? at,
  }
}

/** 事件 → 情绪增量 (只列有把握的几种, 其余不动) */
const AFFECT_DELTAS = Object.freeze({
  talked_to_her:   { valence: +1, engagement: +1 },   // 他主动说话
  replied_her:     { valence: +1, engagement: +1 },   // 她开口之后他接了
  ignored_her:     { valence: -1 },                   // 她开口之后他没接 (ignored +1)
  snapped_at_her:  { valence: -2, arousal: +1 },      // signals 里的负面词命中
  late_night:      { arousal: +1 },                   // 01:00-04:00 还在用
  long_game:       { arousal: +1, engagement: -1 },   // usage 的 game 满 appMinutes
})
```

## 6. L3 关系记忆: 三层 (P1)

### 6.1 三层与文件

| 层 | 文件 | 一行是什么 | 谁写 | 上限 |
| :-- | :-- | :-- | :-- | :-- |
| 情节 | `lw/memory/episodes.jsonl` | `{at, who, what, valence, refs[], open}` 一件值得一提的事 | 她 (工具) + 宿主 (从 `lw/out` / `wishes` 自动补) | 400 条 |
| 画像 | `lw/memory/profile.json` | 他的作息 / 称呼 / 雷区 / 偏好怎么被安慰 | 她 (工具) + 探索收尾建议 | 30 个键 |
| 关系 | `lw/memory/relation.json` | 认识天数 / 亲近度 / 上次冷场 / 被划过的线 | **宿主自动** (事件累加, 不调模型) | 一个对象 |

三层与 ZifaMem 的对应: session summaries → `episodes.jsonl` 的 `what`; episodic memories → 同表
`refs` 与 `valence`; consolidated user model → `profile.json`。区别只在**这里由宿主管结构, 模型只管内容**,
于是不会被模型编造。

### 6.2 新增工具 `lw_memory` (宿主单写者, 与 `lw_wish` 同一手法)

| op | 参数 | 干什么 |
| :-- | :-- | :-- |
| `add` | `what` (≤120 字), `tags[]`, `valence?` | 记一件关于他的事 |
| `list` | `q?`, `limit?` | 按关键词回最近几条 (她答话前查一下) |
| `profile` | `get` / `set {key, value}` | 画像读写 (只认白名单键) |
| `forget` | `id` / `q` | 删 (他要求忘掉时用) |
| `status` | — | 几层各多少条、上次整理时间 |

**为什么给工具而不是自动抽取**: 自动抽取会造谣 ("他喜欢下雨天"), 而工具调用有 `what` 原文可追溯 ——
判据可以拿这条原文与 `episodes.jsonl` 逐字对。

写入纪律 (与 `lw_wish` 相同): 原子写 + 上限 + 越界丢弃; 每一行带 `at`, 文件坏了当空 (不许因此说不出话)。

### 6.3 召回: `relatedEpisodesFor(episodes, cue, now, budget)`

```js
/** 三样打分相加: 词重叠 / 时间衰减 / 未了的事加权 */
function episodeScore(one, cue, now) {
  const overlap = overlapRatio(tokenize(one.what), tokenize(cue))     // 0..1
  const age = Math.max(0, now - Number(one.at || 0))
  const recent = Math.pow(0.5, age / EPISODE_HALF_LIFE_MS)             // 30 天半衰
  const open = one.open === true ? 0.3 : 0
  const warm = Number(one.valence) >= 1 ? 0.1 : 0                      // 一起开心过的更容易想起
  return overlap * 0.5 + recent * 0.35 + open + warm
}
```

预算: 最多 5 条 / 每行 ≤120 字 / 整段 ≤600 字。**召回结果只给"有出处的原话"**, 不给她"印象"。

### 6.4 注入形态

```text
〔记着的几件事〕
- 11-18 「明天上午十点开会」 还没回我 (未了)
- 11-16 「最近连着几天半夜还在打游戏」 他那天有点烦 (说过了)
- 11-09 「想换一把键盘」 只是提了一句
这几件都可以提, 但一次只说一件; 说的时候用他的原话, 别添颜色.
```

最后那句是透明性约束 (G6): 引用必须是原话, 不许加工成"你上次特别难过的时候"。

## 7. L4 共情策略分布 (P1)

### 7.1 五种策略 (与 EMNLP 2025 那篇的策略面同一套)

| 策略 | 什么时候 | 一句话长什么样 |
| :-- | :-- | :-- |
| `companion` 陪 | 他情绪低、话短、深夜 | 「我在」「先靠一会儿, 什么都不用说」 |
| `validate` 确认 | 他被骂、委屈、抱怨 | 「这事儿确实憋屈」「换我也烦」 |
| `advise` 办法 | 他问怎么办、有明确目标 | 「先这样, 再这样」 |
| `distract` 分散 | 他闷但不深、想换个心情 | 「出去走两步? 或者看个短的」 |
| `space` 留白 | 他明确不想聊、连着没回 | 一句, 不追问, 甚至只留一个字 |

### 7.2 选择函数 (纯函数, 判据真跑)

```js
/** (affect, relation, moment) → { lead, avoid, budget, why } */
export function empathyPlanOf(affect, relation, moment) {
  const late = moment?.phase === 'late'
  const cold = Number(relation?.ignored ?? 0) >= 2          // 连着两次没接
  const low = Number(affect?.valence ?? 0) <= -1
  const busy = moment?.busy === true                        // 游戏 / 视频 / 通话
  if (cold) return { lead: 'space', avoid: 'advise', budget: 1, why: 'two in a row unanswered' }
  if (late && low) return { lead: 'companion', avoid: 'advise', budget: 1, why: 'late and low' }
  if (low) return { lead: 'validate', avoid: 'distract', budget: 2, why: 'down today' }
  if (busy) return { lead: 'distract', avoid: 'validate', budget: 1, why: 'he is busy' }
  if (Number(relation?.closeness ?? 0) >= 0.6) return { lead: 'companion', avoid: 'advise', budget: 2, why: 'used to each other' }
  return { lead: 'companion', avoid: 'advise', budget: 2, why: 'default' }
}
```

真值表 (判据直接钉这几行):

| 场景 | 期望 lead | 期望 avoid |
| :-- | :-- | :-- |
| 深夜 + 情绪低 | companion | advise |
| 白天 + 情绪低 | validate | distract |
| 连着两次没接 | space | advise |
| 正在打游戏 | distract | validate |
| 平常 | companion | advise |

`advise` 在缺省与多数场景里都是 `avoid`, 这是刻意的: 情感陪伴里最伤人的一句是"你应该…"。

### 7.3 注入形态 (一行, 打在开场正文的最后一段之前)

```text
这一场主调: 陪着他 (先不给办法). 他刚连着两次没接我, 所以只说一句, 不问第二句.
```

加进 `proactiveStartLine` 的拼装里 (`index.mjs:14525`), 顺序刻意排在"语气"之前、"可以沉默"之后 ——
先读"该不该说", 再读"怎么陪", 最后读"什么口气"。

### 7.4 与"活动板块"的接口

策略不是模型自选, 是**由设置里那几格权重决定**. 于是"她多会安慰人"这件事第一次成了一个可以拨的刻度
(见 §9), 不是一段没法验证的文案。

## 8. L5 边界与透明 (P2)

### 8.1 `lw/memory/boundaries.json` (他划过的线)

```json
{ "v": 1, "at": 1795000000000,
  "items": [
    { "id": "b1", "what": "别提我前女友", "hard": true, "learnedAt": 1794000000000 },
    { "id": "b2", "what": "别劝我早睡", "hard": false, "learnedAt": 1794000000000 }
  ] }
```

- `hard: true` → 判据层直接拦: `lw_say` 的 text 命中该片段就拒发并回一句"这条他划过了" (宿主侧一处硬闸,
  与 `PROACTIVE_*_DENIED` 同一风格);
- `hard: false` → 只进提示词当"注意", 不作硬拦。

写入两条路: 他自己在对话里说"别问了"被识别 (`lw_memory op=add` 带 `hard`), 或她在对话里主动记;

### 8.2 三条"收得住"的规矩 (补 Replika 那个坑)

| 情形 | 现在的表现 | 改后 |
| :-- | :-- | :-- |
| 他说"不想聊" | 提示词没说, 她可能再追一句 | 只回一句, 之后这一场不再开新话头 (`budget = 1`, `avoid = advise`) |
| 连着两次没接 | 路由层 24 h 不发 | 加一条：下一场开口**不许带问句** (`empathyPlanOf` 的 `space`) |
| 他要结束关系 / 换掉她 | 无 | 明确承认"你要是不想我说话, 我就不说了", 并且真的停 7 天 (`relation.mutedUntil`) |

第三条是"干净的分手": 人格完整性包括**尊重他离开**. 实现上一格时间戳 + 一个闸, 成本极小。

### 8.3 透明引用 (G6)

| 要求 | 实现 |
| :-- | :-- |
| "我记得"必须有出处 | 注入片段都是带日期的原话; 提示词要求引用时用原话 + 日期, 不许加工 |
| 不许假装身体在场 | 人格卡"二之二"第 4 条 + 判据词表 (`看着你睡` / `抱抱你` / `摸摸头` 属禁区) |
| 让他看见她在理解 | 门户气泡带 `meta.topicSource` 已有 (`wake` 那一行 `index.mjs:13625`); 扩成 `meta.memoryRef` = 召回条目的 `id`, 抽屉里点开能看"她凭什么这么说" |

第三件是 Paradot 那条路的低成本版: 不把推理全摊开, 只让"她引用了哪条记忆"这条链可查。

## 14. 已知边界 (写清, 免得下一轮又当成 bug)

1. **记忆三层不是"真记忆"**: 它是一份带时间戳的清单, 召回靠词重叠 —— 语义含糊的问 (比如"我上次说的那个事")
   召不回来。真正的向量召回要 dsh-mneme, 而主动场的插件表故意没有它 (见 `presets/proactive/README.md:22-25`)。
2. **情绪是推导值, 不是感受**: `affectStep` 只是把"他多久没说话 / 有没有接 / 现在几点"折成四个数。
   她"心情"的合理性完全取决于这几个信号的质量, 信号错了她会"莫名其妙不高兴" —— 所以每场都要把
   推导依据写进日志 (`affect: v=1 a=1 e=2 phase=late`), 出问题先看这一行。
3. **`advise` 缺省被压住是有意的**: 只在她主动开口时压; 他直接问"怎么办"时不受限 (那是 `luwi` 档的对话, 不走这一层)。
4. **不让模型自己写人格**: 状态与策略都是宿主的纯函数, 模型只负责"说什么"。这一条一旦松掉, MATE 那套
   "确定性内核"就白抄了。
5. **透明不是全摊开**: 只透"这条记忆的出处", 不透"她怎么想出来的"。全摊开会把陪伴变成调试面板 (Paradot 那条路的边界)。
