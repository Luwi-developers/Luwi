# 排期场并入探索 + 判断层开口前台/浮标双发 (2026-11-21)

> 分支 `agent/merge-proactive-into-explore`, 提交 `6b99422`. 只按这一天的代码读数写.

## 做了什么

两条需求合并成一套主动开口机制:

1. **按时间的排期场撤掉**: 主动开口不再由 `ProactiveSchedule` (requestCode 43) 到点开一场,
   也不再按时间跑探索 (requestCode 42). 这两处闹钟不再注册:
   - `DshHostService.onCreate` / `onTaskRemoved` 不再调 `ExploreSchedule.ensure` / `ProactiveSchedule.ensure`
   - `AutomationEngine` 心跳不再调 `ensureIfStale` / `ensureCatchUp`
   - `ExploreSchedule.save` 保存只落配置, 不再 `arm`
   - 宿主 `voiceDeliver` 的 `source:"proactive"` 分支改成丢弃老行 (`skipped`), 不再 `startProactive`
   - 设置页移除「每天几点」「每场多少分钟」与主动对话的排期开关/时刻/解锁; 探索只留步数
2. **探索被判断层触发, 收尾顺带说**: `judgeRouter` 判 `say=true` 且球不在场时, `routerTick` 开一场
   只按步数的探索 (`startExplore { via:'router', speakOnFinish }`), 探索 `finishExplore` 写完摘要/checks
   后把挑好的那句用 `lwOutAppend` 写进本场 lw/out. `speakOnFinish` 跟着 `exploreRun` 落盘/恢复,
   宿主重启也接得回来.
3. **判断层开口双发**: 球在场 (`voiceDelivery.current` 非空) 时, 那句话用 `lwOutAppend(当前场)` 取代
   只往球只读区冒一句的 `reportSay` —— 门户与浮标从同一份 lw/out 读到, 一行一 seq, 不各画一遍.

## 边界与保留

- 宿主内部 `minutes` / `deadline` / `exploreBudget` / `exploreTick` 留着当看门狗兜底, 不再是用户设置.
- `ProactiveSchedule.kt` / `SchedulePanel` / `ProactiveGate` 类与纯函数保留 (设置页读数、30 分钟闸与
  自动指令共用那笔账), 只是不再有写者/闹钟把排期跑起来.
- 「唤醒一下」`routerWakeNow` 仍走 `startProactive` 与 proactive 预设 —— 人当面戳的那一下不是排期.
- 静默 / 冷却 / 退让 / 打扰成本 / 概率递增 (`chatChanceStep`) 全部留在 `judgeRouter`, 行为不变.
