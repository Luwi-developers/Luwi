# Luwi 门户对 dsh 的模态窗让路（2026-11-14）

## 现象（主人 2026-11-14 原话）

> 这个窗口只在进入后台时才会展示, 用户才能登陆并使用模型, 这会导致如果在前台时永远看不到这个弹窗也没办法登陆, 同时也无法使用 accout 模型, 之前要求的这个弹窗应显示在新手弹窗之后的任务没有落实到位

截图里那一窗是 dsh 自己的「开始使用」: 标题 + `登录 DeepSeek 账号, 或添加 API Key, 即可开始使用` + `添加 API Key` / `登录` 两颗按钮。

## 根因

1. 那一窗是 `SignInDialog`（`ui-settings-account`），由首启引导步 `DeepSeekOnboardingDialog`（`ui-settings-models`）经 `settings.models.sign-in` 槽渲染；它走 `ui-primitives` 的 `Modal`，`createPortal(..., document.body)`，层级 **1000**。
2. Luwi 门户 `build()` 里 `document.body.appendChild(#lwp-root)`，样式 `position: fixed; inset: 0; z-index: 2147483000`，同时把 dsh 的 `#root` 设成 `visibility: hidden`。两者都是 body 的直接孩子，**门户层级高出三个数量级**。
3. 门户开关 `readSwitch()` 缺省就是 `on`，`apply()` 里 `if (readSwitch() === 'on') portal.mount()` —— 首启照样自动挂上。
4. 于是顺序变成：加载界面 → 原生「开始使用」引导（独立 Window）→ 关掉引导 → **门户**；dsh 的登录窗一直在门户底下。点浮标菜单「回到后台」= `hide()` → `writeSwitch('off')` + `unmount()`，门户连同 `#root` 的 visibility 一起撤掉，登录窗这才露出来 —— 这就是"只在进入后台时才会展示"。

`#39` / `#44` 那两单只调整了"加载界面 / 引导"的先后，没处理紧接着盖上来的门户，所以"这个弹窗该在新手弹窗之后"没有真正落地。

## 做法

不动 dsh 一个字节，也不改门户的全局 `z-index`（`ui-primitives` 里 Menu / Toast / Tooltip 都是 1100，压层级会把它们一并翻到门户上面），只让门户在两件事上退让：

| 时机 | 门户的动作 | 判据 |
| :--- | :--- | :--- |
| 首启引导还开着 | **先不自动挂**（每 500 ms 问一次 `portalStatus().guide`，最多 60 s，读不到 / 用尽照旧挂） | `ReadyCard.kt` 的 `GettingStarted.guideOpen` → `PortalBridge.portalStatus()` 的 `"guide"` |
| 屏上还有 dsh 模态窗 | **也不挂**（最多等 5 分钟，见下方"为什么挂不得"） | `document.querySelector('[role="dialog"][aria-modal="true"]')` |
| 屏上真有 dsh 模态窗（门户已经挂着） | **让位**：`#lwp-root` 隐藏 + `#root` 恢复可见 + `portalVisible false` | `document.body` 的 `childList` 观察同一个选择器 |
| 那一窗（连同紧随的下一窗）都关掉 | **回来**：`#root` 先藏、门户再放出来 + `portalVisible true` | settle 250 ms（登录 → 填 Key 是两窗换手） |

**为什么"屏上有窗时不能挂"，只让位不够**（2026-11-14 真机读数）：`mount()` 要 `restore()` 那一场会话，而 dsh 的引导步挂在"主会话是空的"上（`SettingsRoot` 的 `onboardingActive`）—— 点「回到前台」挂上门户之后 **0.8 s 内「开始使用」那一窗就没了**（logcat：`steps aside` → 820 ms 后 `the dialogs are gone`）。所以挂载前那一趟必须等它。

**只让位也不够，还有三处会动 dsh 会话**（同一天第二组真机读数）：门户已经挂着、dsh 才弹窗的那一路，`switchTo`（账本 / 会话表）、`autoStart`（挂上 800 ms 后自己开一场）、`pollLedger`（每 3 s 一拍，里面还有 `openBallWorkspace`）照样会把"主会话"换成非空的那一场，那一窗同样在 1.4 s 内自己关掉（`steps aside` → `the dsh dialog is gone`）。所以让位期间这三处一律停：`switchTo` 回 `false` 并留一行 `dropped: a dsh dialog is up`，`autoStart` 每 500 ms 再试（不记 `autoStartTried`），`pollLedger` 直接返回。让位结束后的下一拍会把该换的那一场补上。

让位**不是 unmount**：开关 `dsh.luwi.portal` 不动、`clearOut` 不调、`startSession` 不调、会话不换 —— 撤掉再重建会丢她在那一段说的话（#38 的账）。

`portalVisible(false)` 是必须的：宿主据此把 WebView 让给键盘，否则「添加 API Key」那一步的输入框会被键盘压住。`isOpen()` 算上让位（让位时屏幕上确实是 dsh 的界面，菜单写「回到前台」）；`__LUWI_PORTAL__.show()` 先撤让位再按挂没挂走（主人点名要看门户时门户优先）。

## 判据

- `node tools/check-luwi-portal.mjs`（359 条）：选择器字面量、让位/回来各一次 `portalVisible`、观察器不开 subtree、`unmount` 摘观察器、`isOpen` 算上让位、`show()` 先撤让位、引导闸 fail-open；并抽出 `yieldToDshDialog` 的函数体断言里面**没有** `clearOut` / `writeSwitch` / `startSession` / `unmount(`，`resumeFromYield` 是"先藏 `#root` 再放出门户"。
- `node tools/check-ready-card.mjs`（28 条）：`guide` 那份读数由 `guideShown` 写、`prepare()` 归零、离组合归零，`PortalBridge` 读它。
- 真机/模拟器读数见落实表；正常机器（已登录）冷启**不该**出现任何 `[luwi-portal] … steps aside`。

## 怎么整块撤

删掉 `presets/luwi-portal/lib/client.js` 里的 `DSH_DIALOG` / `YIELD_SETTLE_MS` / `GUIDE_WAIT_MS` / `GUIDE_WAIT_TRIES` / `DIALOG_WAIT_TRIES` 五个常量、`dshDialogUp` / `yieldToDshDialog` / `resumeFromYield` / `watchDshDialogs` / `stopDshDialogs` / `syncDshDialogs` / `mountWhenPageClear` 七个函数与 `yielded` / `dialogObserver` / `dialogSettleTimer` 三个变量，把 `mount()` 里的 `watchDshDialogs()`、`isOpen` / `dialogUp` / `resume`、`show()` 与 `apply()` 的自动挂载还原；Kotlin 侧删掉 `GettingStarted.guideOpen` / `guideShown` 与 `portalStatus()` 的 `"guide"` 一行。上游若哪天自己把登录窗画到门户之上，这一层就可以整块撤。

## 附录: 引导里的「账号」一项 (2026-11-14 第二轮, 主人: "直接调用 dsh 的登陆接口")

页面里那扇「开始使用」终究是 dsh 的窗, 门户怎么让位都还隔一层。这一轮把它搬到**原生引导卡**里: 竖轨上多一行「账号」, 点开是原生那一窗 —— 账号状态、`去浏览器登录`、`填一把 API Key` 全在 Luwi 这一侧完成。

| 层 | 做什么 | 判据 |
| :--- | :--- | :--- |
| `host-plugin/index.mjs` | 新增 `POST /lw-account` (只认回环两头、只收 POST、正文 ≤8 KB): `status` = `deepseekAccount.getState` + `getProfile` + `credentials.resolve('DEEPSEEK_API_KEY')`; `login` = `deepseekAccount.startSignIn(client, origin, 'web')` (地址没随那一帧到就跟一段 `watch`, 12 s 上限); `key` = `credentials.set`, **空串 = `credentials.unset`** | `check-luwi-portal` 第五节 |
| `presets/luwi-portal/lib/client.js` | `__LUWI_PORTAL__.account('status'\|'login'\|'key')` 转发那一条 `fetch('/lw-account')`, 结果经 `PortalBridge.lwAccountResult` 报回原生 | 同上 |
| `ui/PortalAccount.kt` | 那一份状态 (未登录 / 已登录谁 / Key 已保存 / 没成的原因) + 三个动作的入口 | 同上 |
| `ui/ReadyCard.kt` + 两份 strings | 竖轨上「账号」一行 (与「选择权限」同款), 点开是 `InputDialog` 那一窗; 授权地址一到就交给系统浏览器, `ON_RESUME` 再问一次状态 | `check-ready-card` 第十三节 |

**为什么不在页面里调 `remote.account`**: 那是 dsh 开给**自家账号页**的缝, 第三方插件直接调会一声不响地挂住 (第一轮真机读数: `asking the page: account('login')` 之后 12 s 没有任何回话; 加 `remoteAccess.whenAccess('account/watch')` 包裹也没用)。搬到宿主进程里之后一次就通。
