# 填写窗居中、键盘不压：`InputDialog` 统一壳 (2026-11-14)

## 0. 一句话

设置里那些"要打字"的弹窗 (数字手打 / 时间 / 单行 / 多行) 一律**在屏幕中间出现**, 键盘弹起时整窗让出
那一段, 输入框与「取消 / 确定」始终看得见。做法是**一个壳** (`scaffolds/InputDialog.kt`) 加 24 处
一行替换 —— 业务逻辑、落盘、文案一个字节没动。

## 1. 口径: 主人这一轮定的

> 设置里所有这类自定义数字或内容设置，填写窗放屏幕中间，防止弹出键盘时挡住填写内容。

## 2. 现状: 为什么原来会被压住 (三条都是量出来的)

| # | 事实 | 怎么量到的 |
| :-- | :-- | :-- |
| 1 | Miuix 0.9.4 的 `DialogContentLayout` 是 `if (largeScreen) Alignment.Center else Alignment.BottomCenter` —— **手机上默认贴底** | `javap -c` 反编译 `miuix-ui` 的 `DialogContentLayoutKt` |
| 2 | 想靠 `largeScreen = true` 居中, 它会把窗画进 root scaffold, 于是**嵌套场景** (门户「更多设置」→ 数字窗) 被外层弹窗整个盖住, 现象是"点了没反应" | 2026-11-14 00:15 真机 A: 点「唤醒的最短间隔」毫无反应, `dumpsys window` 只有 MainActivity 一个窗口 |
| 3 | 它自己起的窗口按默认 `decorFitsSystemWindows` 把 ime insets 吃掉: 内容里 `WindowInsets.ime` 恒 0, `imePadding()` 没用; 任务卡那张长文本窗的「确定」被键盘压住 | 2026-11-14 00:27 真机 A 截图 |

`WindowCompat.setDecorFitsSystemWindows(window, false)` + `ViewCompat.requestApplyInsets()` 这两下没救回来
(仍然是 0) —— 那一窗不是我们能安排的。

## 3. 解法: 用 Compose 自己的 `Dialog`

`scaffolds/InputDialog.kt`:

```kotlin
Dialog(
    onDismissRequest = { onDismissRequest(); onDismissFinished?.invoke() },
    properties = DialogProperties(usePlatformDefaultWidth = false, decorFitsSystemWindows = false),
) {
    Box(Modifier.fillMaxSize().imePadding().padding(horizontal = 20.dp, vertical = 24.dp),
        contentAlignment = Alignment.Center) {
        BoxWithConstraints(Modifier.fillMaxSize(), contentAlignment = Alignment.Center) {
            val cap = minOf(maxHeight, (screenHeight * heightFraction).dp)
            Card(Modifier.fillMaxWidth()) {
                Column(Modifier.fillMaxWidth().heightIn(max = cap)
                    .verticalScroll(rememberScrollState())
                    .padding(horizontal = 20.dp, vertical = 20.dp)) {
                    Text(title, style = textStyles.title3, color = colorScheme.onSurface)
                    summary?.let { Text(it, style = textStyles.body2, color = colorScheme.onSurfaceVariantSummary) }
                    Column(Modifier.padding(top = 16.dp), content = content)
                }
            }
        }
    }
}
```

三件事各归各位:

1. **居中** = `Box(fillMaxSize).imePadding()` + `Alignment.Center`; 键盘起来时这个 Box 变矮, 窗就落在
   "键盘上面那一段"的正中
2. **不压住** = 同一层的 `imePadding()` (Compose 的 Dialog 关掉 `decorFitsSystemWindows` 之后 **拿得到
   ime insets**, 这是它与 Miuix 那层窗口的区别)
3. **长文本不撑出屏** = `BoxWithConstraints` 把 `maxHeight` 当上限, 再与 `heightFraction × 屏高` 取小的
   那个, 内容在卡片里滚 —— 底部按钮永远在卡片里、卡片永远在键盘上方

卡片与文字仍是 Miuix 那套 (`Card` / `colorScheme` / `textStyles`), 观感与别的弹窗一致; 只是标题从
"居中一行"改成"左对齐一行", 与设置页的层级读法一致。

## 7. 风险与不做

- **视觉换了壳**: 标题从左对齐改成了设置页那种左对齐一行; 弹窗底没有 Miuix 的进出动画 (Compose Dialog
  默认那一下淡入)。若主人要"和别的弹窗一模一样", 得等 Miuix 上游给 `OverlayDialog` 一个"居中 + 不吃
  insets"的档, 我们不再自己造第三套
- **不粘键盘**: 键盘高度取的是 insets, 悬浮键盘 / 分屏下按各 ROM 报上来的算
- 不动任何 `SuperTextField` 的焦点与输入逻辑; 不动保存路径; 不新增字符串键
