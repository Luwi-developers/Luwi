# 主动场读屏 + 默认人格 方案 (2026-11-10)

两份东西放在一份里, 因为它们互相咬:

1. **主动对话先看一眼当前屏** —— 无需权限请求, 只读, 读完删除, 不可残留截图
2. **默认人格** —— 先说清现在是谁 (文件在哪), 再给这一版的默认人格设计

## 0. 结论摘要

| 问题 | 结论 |
| :-- | :-- |
| 主动场现在看不看屏 | 不看, 开场读探索摘要 / 记着的事 / 日历 / 通知 (见上一轮的回答) |

## 1. 目标与不变量

**目标**: 主动场到点醒来时, 先知道"主人此刻在干什么" (哪个应用 + 一屏的文字), 再决定开不开口.

**不变量 (任一条破就是方案错)**:

1. **不弹任何权限请求** —— 不出现 MediaProjection 的授权框, 不出现"允许截屏"的系统弹窗. 现有无障碍与特权通道 (Shizuku / root) 是装的时候一次给好的, 不算请求
2. **只读** —— 不点、不滑、不打字、不建虚拟屏、不改设备状态
3. **图不落地超过一次调用** —— 截出来的 PNG 在 `finally` 里删掉, 且删完要能验; 崩溃 / 进程被杀留下的那一张, 下次启动或下次调用前扫掉
4. **不给持久图片** —— 不写工作区, 不写 `$DSH_HOME`, 不进 dsh 附件库, 不进相册, 不进 `lw_say` 的图
5. **文字也要收口** —— 只交"能判断要不要开口"的那点字; 验证码 / 密码 / 长数字在应用侧就打码, 原文不过桥
6. **看得见 ≠ 说得出来** —— 人格层明确: 她可以看, 但不转述屏上的原文 (这条与现有红线第 20 条同一口径, 只是现在要正面写)

## 2. 现状: 为什么不能直接复用现成那条路

### 2.1 `lw_screenshot` (displayId 0)

- 落在 `<工作区>/screenshots/screen-0.png`, 而且**同名覆盖**留着 (`VirtualScreen.kt:629` `File(screens(), "screen-${screen.displayId}$suffix.png")`), 目录注释就写着"the model can read and the user can open it" (`VirtualScreen.kt:757-761`)
- 主屏这一档走特权进程 `screencap -p` (`VirtualScreen.kt:740-755`), 拍之前先落到 staging
- 结论: 它就是"要留一张"的工具, 主动场不能用

### 2.2 `lw_ocr` (端侧 OCR)

- 不写工作区, 只拿 `Bitmap` (`VirtualScreen.kt:791-821`) —— 方向是对的
- **但主屏那一路的 staging 文件从来不删**:
  - staging 路径建在 `/data/local/tmp/lw-screen-<uuid>.png` (`VirtualScreen.kt:171-176`, `SHELL_SCRATCH = "/data/local/tmp"`, `VirtualScreen.kt:852`)
  - 特权进程只能写 shell 的 scratch (app 沙盒它进不去), 所以必须落在那儿
  - `capture()` 拍完只 `decodeFile`, **没有 `delete()`** (`VirtualScreen.kt:799-821`); 全仓也搜不到 `lw-screen-*` 的清理
- 也就是说: **现在每调一次 display 0 的 `lw_ocr`, `/data/local/tmp` 里就多一张全屏 PNG, 而且没人回收.** 名字是随机的 (`PICTURE_PREFIX` + UUID), 但那个目录谁都能列. 这一条本方案顺手修掉

### 2.3 内联图片

`lw_look` 那条路是 `render` 里塞 `{ type: 'image', attachment }` (`host-plugin/index.mjs:1980-1998`). dsh 的图片块指向 attachment store (`@deepseek-ai/dsh-attachment`), 是**持久**的 (会话附件, `dsh-attachment-local`), 还会进 token 计量. 所以"把一张图交给模型"这个动作本身就等于"盘上多一张图".

结论: **主动场不交图片, 只交文字**. 这不是省事, 是"不可残留截图"这一条逼出来的唯一解.

## 3. 方案: `lw_glance` (看一眼就走)

### 3.1 工具形状

```
lw_glance()                 # 无参数; 只认一个 note (备注, 与别的工具同一条)
```

- **没有 `displayId` / `x,y,w,h` / `count` / `sheet` / `debug`** —— 参数面就是"不能拿它当截图工具用"
- 返回纯文字, 没有 image 块
- 它不进 A 表 (那张表是"拒"/"放"的屏类工具), 而是进一张只读白名单: 三档都放, 但要过下面那道限流

### 3.2 两个来源, 先便宜后贵

```
lw_glance
  ├─ 1. 屏状态 (DisplayManager.STATE_*)           off / dozing / unknown -> 到此为止, 不拍
  ├─ 2. 锁屏 (KeyguardManager.isKeyguardLocked)   locked -> 到此为止, 不看锁屏
  ├─ 3. 无障碍树 (LwAccessibility.tree(0))       有控件 -> 取文本 + packageName, 零文件
  ├─ 4. 树空 (画布 / 游戏 / Flutter)              -> 特权通道 screencap -> 临时 PNG -> OCR -> 删
  └─ 5. 都没有 (无特权通道 / OCR 没模型)           -> 只报状态与原因, 不猜
```

第 3 步为什么放前面: 大多数应用 (聊天 / 设置 / 浏览器) 的控件树里就有字, 一个字节都不落盘; 树空才走截图, 于是**大部分主动开口根本不产生任何文件**.

第 3 步也顺手解决"她在用什么应用" —— `tree(0).packageName` (`LwAccessibility.kt:401-416`), 再用 `PackageManager` 换成人看得懂的名字.

### 3.3 返回的那段字 (固定形状)

```
screen: on · app: 小红书 (com.xingin.xhs) · display: 0 1080x2400
source: tree, 18 条 / 612 字
---
<至多 40 行 / 1200 字, 已打码>
---
没有留下图: 这次读取没有写工作区, 临时图 0 个
```

`source: tree|ocr`, 失败时是:

| 情况 | 回什么 | 她要怎么办 (提示词里写死) |
| :-- | :-- | :-- |
| `screen: off` / `dozing` | 屏熄着, 没拍 (熄屏时 `screencap` 会交最后一帧, 那是旧的) | 不猜, 按摘要与通知决定 |
| `screen: locked` | 锁屏着, 没看 | 同上 |
| 无特权通道 | "这台设备没有特权通道 (Shizuku / root 没给), 看不了屏" | 如实说, 不换路 |
| OCR 没模型 | "端侧 OCR 这台没有模型" | 如实说 |
| 树是空的且截图失败 | 带 `VirtualScreen.lastError` 那一句 | 如实说 |

### 3.4 限流 (硬闸, 不在提示词里)

- `proactiveRun` 里记 `glances`: 一场主动对话**最多 3 次**, 两次之间 ≥ 1 s
- 超过就拒: `refused: lw_glance already ran 3 times in this conversation` —— 防"看一眼 -> 再一眼 -> 死循环"
- 主动场之外 (对话 / 球) 另给一个上限: 按 session 记 20 次/场, 免得它变成 `lw_ocr` 的廉价替代

### 3.5 时序 (一次成功读)

```
主动场到点
  -> 应用: 屏状态 / 锁屏 / 通道 三项前置 (全本地, 无权限弹窗)
  -> 应用: tree(0) 取文本  ── 有 -> 打码 -> 回文字
  -> (树空) 应用: 先让特权侧扫掉陈旧的 lw-glance-*
  -> (树空) 应用: 特权侧 screencap -> /data/local/tmp/lw-glance-<uuid>.png
  -> (树空) 应用: decodeFile -> OCR -> recycle
  -> (树空) 应用: finally { 特权侧删除那一张; 自己 stat 复核 }
  -> 应用: 打码 -> 回 { state, app, lines, ms, deleted }
  -> 宿主: lw_glance 回文字 -> 模型
  -> 模型: lw_say (一两句) 或 沉默
```

一次调用的墙钟预期: 树路 50~200 ms; OCR 路 400~1200 ms (沿用 `lw_ocr` 的读数). 主动场一次, 代价可以接受.

**删除为什么必须过特权侧**: `/data/local/tmp` 是 shell 那个 uid 的 scratch (一般是 `0771`, 属主 `shell`), app 自己的 uid 只能**按名字**读它 (目录有 x 没有 w), 删不掉 (`VirtualScreen.kt:156-176` 那段注释就是这个意思). 所以给协议加一个只做"删自己那一类临时图"的动词, 不给通用删除:

- `SCRATCH` (新的 binder 动词, `LwServiceProtocol` 顺延): 只认两种 op
  - `sweep`: 删掉 `/data/local/tmp` 下 `lw-glance-*` 与 `lw-screen-*` 里超过 N 秒的
  - `remove`: 删掉**一个**指定路径, 必须在这两个前缀里
- 特权侧写死: 父目录必须是 `/data/local/tmp`, 基名必须以 `lw-glance-` 或 `lw-screen-` 开头, 不递归, 不做 shell 展开
- 这一条同时也是修 2.2 那个泄漏的那一刀: `lw_ocr` / 截屏的 staging 从此有人收

## 4. 零残留: 五道关

| 关 | 做法 | 验证 |
| :-- | :-- | :-- |
| 1 临时图 | 只一处: `/data/local/tmp/lw-glance-<uuid>.png`; 名字带 UUID (目录可遍历, 名字不可猜) | 调用后 `ls /data/local/tmp/lw-*` 为空 |
| 2 删除时机 | `try/finally` 里走特权侧 `SCRATCH op=remove`, 再自己 `stat` 复核 (app 按名字 stat 得到, 删不掉); 失败留一行日志 (不带正文), 回答里如实写 `deleted: false` | logcat 有一行 `staging removed`; 文件不在 |
| 3 清扫 | 每次截图前 `SCRATCH op=sweep` 清 `lw-glance-*`; **应用启动时也扫** (`initialize()` 之后, 通道就绪时); 顺手扫 `lw-screen-*` (修 2.2 的泄漏) | 杀进程再起, 目录仍为空 |
| 4 不落别处 | 不写工作区 / `$DSH_HOME` / 附件库 / 相册; 不碰 `lw_say` 的 image; OCR 不写 debug 图 (`debug=false`) | `screenshots/` 无新文件; 会话里没有 image 块 |
| 5 文字 | 打码后过桥; 日志与审计只记条数 / 耗时 / 状态, 不记正文 | `check-glance.mjs` 抽打码函数真跑; logcat 无屏上文字 |

打码规则 (应用侧 `GlanceRedaction`, 纯函数, 单测钉着):

- 整行含 `验证码` / `密码` / `确认码` / `动态码` -> 只留关键词, 数字换成 `〔已打码〕`
- 独立数字串 4~8 位 -> `〔n 位数字〕`
- 连着的 ≥ 9 位数字 (卡号 / 手机号 / 订单号) -> `〔长数字〕`
- 邮箱 / 手机号形态 -> `〔联系方式〕`
- 打码后再截断到 40 行 / 1200 字 (先打码再截, 别把半个验证码留在边界)

## 5. 主动场接线

### 5.1 硬闸

- 新增 `PROACTIVE_READ_ONLY_ALLOWED = new Set(['lw_glance'])`; `proactiveGate` 第一步先看它: 在里面就返回 `undefined` (三档都放), `full` 档顺手记一行审计
- A 表 (21 条) 一个字不改: `lw_screenshot` / `lw_ui` / `lw_ocr` 在 `remind` / `act` 两档照旧拒
- `act` 档的拒文案改一句: "屏不碰" -> "不建屏、不点屏; 只允许看一眼当前屏 (`lw_glance`)" —— 文案与闸必须逐格一致, 现在那句会与白名单打架
- `check-proactive.mjs` 加三条: 白名单里有 `lw_glance` / 三张表里都没有它 / `act` 档拒 `lw_screenshot` 时文案提到 `lw_glance`

### 5.2 开场顺序

`proactiveStartLine()` 现在注入的顺序是"探索摘要 -> 记着的事 -> 日历 -> 通知摘要". 改成:

```
0. 先 lw_glance 看一眼主人此刻的屏 (只读, 不留图)
1. 最新探索摘要: <path>
2. 记着的事 (lw_wish op=list)
3. 今天的日历
4. 通知摘要
5. 决定要不要开口
```

同时在注入里补两条规矩:

- 看到的字只用来判断"要不要开口 / 说什么方向", **不原样念出来**, 不贴界面原文
- 屏是熄的 / 锁着 / 看不了 -> 照常按摘要与通知决定, 不许拿"看不到"当不开口的理由

`presets/proactive/cordis.patch.yml` 的第一节按同一段改 (1~6 条前面加第 0 条), 第 12 条 ("不贴界面上看到的原文") 保留并加一句"看屏那一眼只是用来判断".

### 5.3 开关

`sim.json` 加 `proactive.glance` (缺省 `true`), 设置 → 活动 → 主动对话 加一行「允许她看一眼当前屏」:

- 关掉时: `lw_glance` 在主动场被拒; 开场正文不写第 0 步
- 默认开着, 因为主人这次要的就是它; 但"看一眼屏"这件事得能在设置里看见, 不能藏在提示词里

### 5.4 兜底

- 主动场解锁开关 (`proactive-schedule.json` 的 `unlock`) 关着且屏锁着: 只报 `locked`, 不为了看一眼去解锁 —— 解锁是另一件事, 归那个开关
- 宿主侧无特权通道时的主动场: 走树路; 树也是空 (画布) 就退成"照摘要开口", 一次都不重试

- 红线: 验证码 / 密码 / 聊天原文 / 金额 / 住址 / 联系方式 不念不抄不记; 不主动外发
- 三种场: 陪聊 (一两句) / 干活 (工程规矩) / 主动场 (各走各的预设)

**这套人格的问题** (这次要改的):

1. **群聊底色还在** —— 规矩是从 qq-chat-v2 搬来的, 那套是"在群里不被冷场"的写法; 现在她一个人待在私人手机上, 需要的不是"会接梗", 而是"知道什么时候不必说话". 第 5 条已经写了"不是每条都要回", 但没给判法
2. **没有"看"这一层** —— 她能看屏, 但人格里只有"屏幕上看不到的事不要猜", 没有"看见了也未必说". 加了 `lw_glance` 之后这一条必须正面写, 否则她容易把屏上的字念出来
3. **称呼与温度只有一条** —— "主人"是定的, 但"怎么对他"没有轴: 太冷像工具, 太热像客服, 现在靠 24 条规矩的边角在暗示

## 9. 风险与回滚

| 风险 | 处理 |
| :-- | :-- |
| 读屏被当成偷看 | 设置里那一行 + 开场正文写明"只读一眼, 不留图"; 打码在应用侧做, 原文不过桥 |
| 无障碍树文本太长 | 40 行 / 1200 字上限, 先打码再截断 |
| 熄屏时拍到旧帧 | 屏状态前置: `off`/`dozing` 直接不拍, 这是已有代码里踩过的坑 (`VirtualScreen.kt:771-788` 的注释) |
| 特权通道缺失 | 树路照用; 都不可用就如实说, 不引 MediaProjection |
| 她反复看 | 硬限流 3 次/场 + 1 s 间隔, 在宿主侧判 |
| 新特权动词被当成通用删除 | 只认 `/data/local/tmp` + 两个前缀 + 不递归, 特权侧写死, 判据里有一条反例 |
| 人格改完不像 | 一步一回滚: 预设是文件 (改回去即可), 卡片是文件, 内核一条记忆 (`memory_update` 换回旧文本) |

回滚顺序: 关 `sim.json` 的 `proactive.glance` -> 撤开场第 0 步 -> 撤 `lw_glance` 白名单 -> 回到 P0 之前 (工具留着但主动场不用).
