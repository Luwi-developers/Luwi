# 门户时间线: 全部消息按时间合并 (2026-11-14)

## 0. 一句话

门户里的气泡**按时间排一条线** —— 门户记录 (`carried`) 那一段不再盲接在头上, 冷启 / 换场那一拍
读到的"半截线"也不再被冻进记录。

## 1. 现象

主人 2026-11-14 截图 (`today 12:18` 那一段):

```
她  12:18  嗯，收到
她  12:30  在，什么事
我  12:18  －－
我  12:30  你好
```

主人的话: "门户又出现了这种消息排序的问题，把全部消息按时间排序"。四条气泡**都有时间标签**。

## 2. 根因 (读代码 + 真机数据确认)

设备: 真机 A `OJZD5D6TMNSKFYHM`。相关数据都在盘上:

| 来源 | 值 |
| :-- | :-- |
| 会话 `session-caa61eb2-…` 的 `user/message` | `u1=1794629931284` (`－－`), `u2=1794630638306` (`你好`) |
| `lw/out/<同一场>.jsonl` 的 `at` | `r1=1794629935111` (`嗯，收到`), `r2=1794630639882` (`在，什么事`) |

用**源码里的真函数 + 上面四个真时刻**跑:

| 输入 | 结果 |
| :-- | :-- |
| 只有本场: `orderTimeline(users, rows)` | `u1 → r1 → u2 → r2` (本来就对) |
| `appendRecord(carried, …)` 头部垫了 `[r1, r2]` | `r1 → r2 → u1 → u2` —— **正是截图那一屏** |
| 合并后按时间重排 (`mergeTimeline`) | `u1 → r1 → u2 → r2` |

所以根因是 **`nodesOf()` 的 `appendRecord(carried, …)`**: 门户记录那一段**无条件接在最前面, 之后再不
重排**。而 `carried` 会被冻进一条**半截线** —— 冷启 / 自动换场那一拍, 她的行是从
`lw/out/<会话>.jsonl` **同步**读到的, dsh 的 user 节点还在**异步**加载, `nodesOf()` 这时只排得出
`[r1, r2]`; `carryRecord()` 把它抄进记录。于是「她的话」整组压在自己的消息上面, 而且只有
「开新对话 / 点历史」才会清 —— 表现就是"又出现了", 不会自愈。

## 3. 改法

| 文件 | 改什么 |
| :-- | :-- |
| `presets/luwi-portal/lib/client.js` | 新纯函数 `mergeTimeline(record, live)`: 先 `appendRecord(live, record)` 按身份去重 (**live 在前**, 同身份以当前那份为准) → 按 `time` 升序**稳定**排 (`time <= 0` 的整段沉到最后) → 尾部截到 `RECORD_MAX`; `nodesOf()` 返回 `mergeTimeline(carried, orderTimeline(users, rows, extras))`; `carryRecord()` 加 `lastUsers === 0` 闸门 (那一拍没有 user 节点就不抄); 模块级 `lastUsers` 由 `nodesOf()` 每次落 |
| `tools/check-portal-order.mjs` | 第六节: 抽 `mergeTimeline` 真跑 6 条 (回归 / 跨场历史 / 同刻稳定 / 缺时间沉底 / 身份去重留 live / 240 截尾) + `carryRecord` 闸门一条 |
| `tools/check-luwi-portal.mjs` | 两处旧字符串 (`appendRecord(carried, orderTimeline(`) 改成 `mergeTimeline(carried, orderTimeline(` |
| `AGENTS.md` | 「时间线按轮排」那一条补上"跨门户记录按时间合并" |

三条口径 (为什么不是"纯按时间"):

1. **轮内仍是轮**: `orderTimeline` 那套 (`user → 她的行 → error → 兜底`, 同毫秒算上一轮) 一个字没改;
   `mergeTimeline` 是**稳定**排序, 同刻的先后原样保住
2. **缺时间沉底**: `time` 读不到的整段排到最后, 内部按原相对顺序 —— 不拿 1970 去比
3. **条数只增不减**: 同一身份只留一条, 上限 240 从尾部截

副作用与代价 (明确接受): 真的是"一个 user 消息都没有"的场 (纯主动场) 也不再跨场抄它自己的行 ——
那份 jsonl 仍在盘上, 那几句本来也由 `echoes` 那条路进本场时间线。
