# 门户附件条与时间线 (2026-11-10)

## 0. 一句话

待发附件 (图片 / 表情 / 文件) 挪到**输入框上方**并画成 dsh 原生的 64px 缩略图; 点表情**先进待发栏**,
按发送才发。聊天气泡不再只按墙上时钟排 —— `orderTimeline` 按「轮」排, 宿主 turn end 补句的 `at`
钉在轮尾。

## 1. 现象

- 附件 chip 出现在文本区**下面**、工具行上面 (`shots\2026-11-08-attach2.png` 同一现象), 图也只有一行字
- 点表情包 = 立刻发出去, 看不到"待发"这一步
- 主人 2026-11-10: "当前的排序乱了" —— 气泡上下顺序会错 (刚发的那条跑到她上一句回复上面 /
  她的回复掉到新消息后面)

## 2. 根因 (读代码确认)

### 2.1 附件条

DOM 追加顺序: `card.appendChild(els.input)` → `card.appendChild(els.attachRow)` → `card.appendChild(row)`。
dsh 原生 `InputBar.tsx:451` 的 `conversation.input.attachments` slot 在 `DraftEditor` (469) **之前**,
`ComposerAttachments.module.css` 是 64px 方图 + 18px `×` + `.rail` `padding:2px 10px 0; margin-bottom:-6px`。
所以是结构问题, 不是样式; 渲染也只是一颗文字 chip。

### 2.2 排序

1. **两路流只按墙上时钟合并**: dsh 的 user 节点与 `lw_say` 的 jsonl 行放进同一个数组, 只按 `sortAt`
   (time) 排, 没有「轮」的概念 —— 缺时间 / 同毫秒 / 时钟差都会跨轮
2. **缺时间的键是 running max**: `sortFloor` 在循环里取"已见过的最大值 + 1", 而 `kept` 里 user 节点
   全部排在她的行前面 → 刚发的那条还没落时间时, 键比这一轮她的回复的 `at` 还小, 排到她回复上面
   (2026-11-09 那条"用户发的消息也合并到最上方"没修干净)
3. **turn end 补句的 `at = Date.now()`**: `lwOutAppend` 固定取写盘那一刻, 而补句是 `void` 异步写的
   → 补得慢就比下一条 user 消息还新, 上一轮的回复排到新消息后面
4. **兜底正文行会改嫁**: `fallbackAt` 在每条新 user 节点到来时重置, 兜底行的时间/身份挂在
   `lastUserId` / `lastUserTime` 上 → 上一轮的兜底从自己那一轮掉到新消息后面; 宿主补句随后到达时
   还会两句并存再换掉
5. 同毫秒先后靠插入顺序 (user 节点先 push, 她的行后 push), 跨轮相等就翻

## 3. 改法

| 文件 | 改什么 |
| :-- | :-- |
| `presets/luwi-portal/lib/client.js` | 附件行移到文本区前; `.lwp-attach-thumb` 64px + `.lwp-attach-x`; `renderAttach` 图走缩略图、非图走 chip; `sendSticker` → `stageSticker` (先占位再取字节, 不调 `send`); `nodesOf` 收 `users/rows/extras`; 新纯函数 `orderTimeline`; 删 `sortAt`/running max 与她的行的单调 clamp; 兜底只给非 luwi 档并 `pinnedTo: assistantOwner` |
| `host-plugin/index.mjs` | `lwOutAppend(..., atHint)`: `at = max(atHint ?? now, mark.at + 1)`; turn/end 补句传 `event.time` |
| `tools/check-portal-order.mjs` (新) | 抽 `orderTimeline` 真跑 12 条用例 |
| `tools/check-luwi-portal.mjs` | 附件条 DOM 顺序 / 缩略图 CSS / `stageSticker` 不调 `send` / 兜底只给非 luwi |
| `tools/check-lw-out.mjs` | 宿主 `at` 单调 + 补句 `atHint` 两条 |

`orderTimeline` 的口径 (纯函数, 判据原样抽出来跑):

| 规则 | 做法 |
| :-- | :-- |
| 轮内 | `user` → 她的行 (按 jsonl `seq`) → `turn-error` → 兜底正文 |
| 轮边界 | 行按 `at` 归到最后一个 `turnTime < at` 的轮 (同一毫秒算**上一轮**) |
| 缺时间 | user 缺时间 → `maxKnown + 序号` 沉到最后; 行缺 `at` → 最后一轮、按 `seq` 沉后 |
| 时钟回卷 | `turnTime` 单调不减; 早于第一轮的行落前奏桶, user 相对顺序不翻 |
| 定序键 | `(桶, rank, seq, 原下标)` —— 同毫秒不再靠插入顺序 |

`seq` 仍是唯一顺序, `at` 只做显示与拼轴 (`OutFile.kt` 第 2 条), 所以宿主那处 `at` 改动对球无影响。
