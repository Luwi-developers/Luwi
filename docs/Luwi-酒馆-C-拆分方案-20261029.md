## 为什么现在做

Gradle 侧 (app/build.gradle.kts)：

```kotlin
val tavernRoot: File? = File(providers.gradleProperty("luwiTavernDir").orNull
    ?: "D:/apk/Luwi-private/tavern").takeIf { it.isDirectory }

android {
    sourceSets["main"].apply {
        if (tavernRoot != null) {
            kotlin.srcDir(File(tavernRoot, "app/src/main/java"))
        } else {
            kotlin.srcDir("src/tavern-stub/java")
        }
    }
    sourceSets["test"].apply {
        if (tavernRoot != null) kotlin.srcDir(File(tavernRoot, "app/src/test/java"))
    }
}
```

**必须是 `kotlin.srcDir` 不是 `java.srcDir`** (2026-10-29 实测): 这一版 AGP 9 + 内置 Kotlin
只把 `kotlin` 源集里那几个目录喂给编译任务, 往 `java` 里加目录它会当没看见 —— 症状是满屏
`Unresolved reference 'LuwiTavern'`, 而两份文件都在盘上

`-PluwiTavernDir=` 指到别处就能换私有仓；目录不在 = 公开构建，自动落到 `src/tavern-stub`。

## 契约：公开侧只认一个 `LuwiTavern`

`ui/LuwiTavern.kt` (私有侧) 与 `ui/LuwiTavernStub.kt` (公开侧) 声明**同一个** `object LuwiTavern`：

```kotlin
object LuwiTavern {
    val enabled: Boolean                       // stub: false
    val sectionKeys: List<String>              // stub: emptyList()
    @Composable fun summaryEffect(reload: Int) // 设置页那一层读一次读数
    fun tavernSection(
        scope: LazyListScope,
        collapsed: Set<String>,
        onToggle: (String) -> Unit,
    ) = Unit                                  // 私有侧画那一段
    fun tavernEntries(builder: NavEntryBuilder)
    @Composable fun overlays()                // TavernWipeOverlay
    fun handleBack(): Boolean                 // TavernSubPageBack
    fun releaseCache()                        // TavernWebViewCache.release()
}
```

共享文件只调这八个入口，不再 import `luwi.tavern.*` —— 这是「公开侧没有酒馆符号」的判据：
`git grep -l 'luwi.tavern' -- app/src/main` 在公开树上应为空。

## 施工顺序 (每步都能单独回退)

1. **抽壳**：建 `LuwiTavern.kt` (私有侧实现 = 现在那些调用原样搬进来) + stub，改 6 个共享文件；
   酒馆文件仍在原地。判据：`:app:compileDebugKotlin` 过
2. **搬文件**：9 组搬进 `D:\apk\Luwi-private\tavern\`（私有仓另开 git，首次提交记下来源
   `c6aa501`）
3. **接构建**：`luwiTavernDir` / `tavernRoot`，`tools/pack-host.mjs` 加 `--tavern-root`，
   插件与预设都从私有目录拷进树
4. **两套都编译**：`assembleDebug` (有酒馆) 与 `-PluwiTavernDir=` 指向空目录 (无酒馆) 各出一包；
   无酒馆那个用 `tools/apk-bytes.py` + 「条目里没有 tavern」双判据
5. **判据搬家**：`check-tavern*.mjs` 挪进私有仓，`read` 改成「先私有根、再公开根」，默认按兄弟
   目录找 `D:\apk\Luwi`，也可 `--repo <Luwi 仓库>`；公开仓那条 `check-settings-sections` 照旧
6. **公开仓收口**：README 改口径 (「主体开源，酒馆闭源」)，`docs/` 里酒馆施工单留在私有仓
7. **推送**：公开分支只含 1–6 的结果；`tools/lw-api-push.ps1` 照旧 dry run → `-Apply -Tag`

## 推送与历史 (最容易踩的一条)

**公开分支的父提交必须是 `2c61255` (v2.7.9)，不能是 `c6aa501`。**

`c6aa501` 那个提交里就有酒馆 85 个文件；哪怕下一条提交把它们全删了，GitHub 的历史里照样翻得到 ——
"删掉"只影响最新树，不影响历史。所以公开推送不是把本分支直接推上去，而是：

1. 从当前私有树导出一份「无酒馆 + stub」的公开树
2. 以 `2c61255` 为父，把这棵树一次性提交 (tree diff 提交，不带任何中途删除记录)
3. 推这一条提交，`-Tag` 照旧

判据：`git rev-list <公开分支>` 里不出现 `c6aa501`，且 `git log --all -- 'app/src/main/java/io/github/yuloong07star/luwi/tavern'`
在远端查不到东西

## 发布与推送口径

- **2.7.10 这个版本先不推源码**：远端停在 `2c61255`，APK 照常发 Release；等第 4 步两套包都验过再推
- 公开仓与私有仓的关系是「公开 ⊂ 私有」：每次发布前从私有仓导出公开树 (去掉酒馆 + 用 stub)，
  导出物单独一个分支，别在私有分支上直接删文件
- 官网下载直链指着 GitHub Releases，**这套拆分不动它**；仓库仍是 public，链接不受影响
