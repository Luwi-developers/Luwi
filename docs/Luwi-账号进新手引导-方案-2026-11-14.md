## 三、竖轨按顺序卡住

有序清单 = `[通道, 无障碍, 唤醒模型, 语音模型, 选择权限, 账号]`。

- `firstPending` = 第一个"未办"项的下标；**环**只吃前缀（`ReadyRing(done = firstPending)`）。
- 每行的轨道（`drawBehind` 那条竖线）由新参数 `reached = index <= firstPending` 决定 —— **上面有缺口，后面的线不亮**；
  节点仍按各自真状态画（已办就是勾，不撒谎）。
- 顶栏「还差 N 步」按**真实未办件数**算（`missing = flags.count { !it }`）：它说的是"还差几件"，不是"走到哪"。
- `ReadyActionRow` 的 `next` 保持"四件里第一个未办"，不动。

### 2026-11-15 补的三条（主人看图后点的）

1. **轨道必须连到底**：`ReadyLinkRow` 原来是写死 `last = true`，于是「选择权限」那一行在自己节点下面就收口了，
   下面的「账号」那颗点悬在半空。改成 `last` 是参数，**只有真末行（账号）才 true**，「选择权限」传 `false`。

## 八、下载能暂停 / 能取消（2026-11-15 晚）

主人: "下载加个暂停, 点击正在下载可暂停, 右边在暂停后显示 … x, 可取消"。

- 两个下载器 (`wake/WakeWordDownload.kt`, `voice/SpeechModelDownload.kt`) 的 `Phase` 多一档 `PAUSED`:
  **暂停 = 断连接 + 保留 `.part`**; 继续时带 `Range: bytes=<已有>-`, 服务器回 206 就从断点接, 回 200 就从头来;
  **取消 = 清 `.part`** 回 `IDLE`。sha256 改成下完整文件重算一遍 (续传不做增量, 239 MB 本地读一次比"拼
  sha256 状态"稳)。
- 卡片: 下载中**点那一行 = 暂停**, 暂停后**点行 = 继续**, **右侧那一格变 ×** (作废这次下载), 底部那颗按钮
  暂停后变「继续 语音模型」。节点在暂停时画两道竖杠 (与打勾同一套笔画)。
- 三条真机上踩出来的坑 (改之前都以为是"应该没事"):
  1. `call.cancel()` / `disconnect()` 抛的是 IOException, 原来被 `fetch` 当成"镜像下不下来" → 一按暂停就
     变红报错 (`stream was reset: CANCEL`)。现在 `fetchOnce` 里判: 有停的意图就把异常转成内部 `Stopped`;
  2. **暂停之后下载线程已经退出**, 再点 × 只设了意图没人接 → 界面停在"已暂停"不动。`cancel()` 现在看
     `running`: 线程不在了就**就地收尾** (`settleCancel`);
  3. `pause()` 当场就把 `phase` 翻成 `PAUSED` (不等线程收尾), 界面上点一下立刻有反应。
