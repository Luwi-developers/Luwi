# dsh 后台键盘让位: 改成「门户那样」(2026-11-22)

主人原话: 「luwi 中 dsh 后台吃出键盘时卡顿严重, 改成像门户那样提高帧率, 当然如果 ui 插件已经实现了这个
需求, 你升级就行, 不然就修正」。

结论: 升级解决不了, 按「修正」办 —— 页面那一层补一个入口, 宿主不再逐帧缩 WebView。

## 一、量到的现场

- 改前这一路是**逐帧缩 WebView**: `HostScreen` 里
  `modifier = if (portalOpen) modifier else modifier.padding(bottom = imeLift)`。
  IME inset 在 Compose 里是逐帧的动画值, 所以呼一次键盘这块 WebView 被 resize 二十来次, 每次都换 surface
  + 全页重排 + 重栅格 —— 卡顿就在这一串里。门户 (2026-11-09 起) 早就不这么干, 它只把高度推给页面。
- UI 插件 `dsh-web-mobile@3.3.5` (`tools/pack-host.mjs` 钉的版本) 已经做了「手机壳高 = 可见带」, 但可见带的
  来源是视口本身:
  - `src/client/styles/layout.css.ts`: `html [data-mobile-nav="frame"] { height: var(--dsha-mobile-visible-vh, 100%) !important }`
  - `src/client/effects/viewport-meta.ts`: `available = min(innerHeight, visualViewport.height)`, 而且**停稳才发布**
    (它自己的注释写着: 逐帧发布 = 整页重排 20 次 + 白屏 1-2 s)
  - 同一份注释还写着参照实现是**一步跳变**的引擎 (「DSHA 壳不逐帧改 WebView 尺寸, 键盘动画的起止各一步跳到终值」)
  → 插件没有「宿主/外部给键盘高度」的入口。查过 npm registry: 最新 `3.3.6` (2026-11-19) 的 changelog 讲的是
  抽屉手势 / 平板预览 / 插件页排版, **没有一条**碰 IME 或帧率, peer 范围也没变 —— 所以**不动 3.3.5 这个 pin**。
- dsh 自己的会话滚底认 resize (`ui-chat` 的 `ResizeObserver` → `onResize()` → `followingTail` 时 `followTail()`),
  输入座位是 `position: sticky; bottom: 0` —— 壳一收高, 它自己就贴到可见带底, 页面这一侧不用补滚动逻辑。

## 二、两条通道 (契约)

| 场景 | 谁抬 | WebView 尺寸 |
| :-- | :-- | :-- |
| 门户盖着 | 门户写 `--lwp-ime` (2026-11-09 起不变) | 不动 |
| dsh 后台, 页面有 `window.__LUWI_IME__` | 页面写 `--lw-dsh-ime` + `data-lw-ime` (ui-fix 第三节) | **一次都不动** |
| dsh 后台, 页面接不了 | 宿主缩 WebView, 只收「停稳」的终值 | 2 次 |

页面那一侧 (`presets/ui-fix/lib/client.js`):

```css
html[data-lw-ime="on"] [data-mobile-nav="frame"] {
  height: calc(var(--dsha-mobile-visible-vh, 100dvh) - var(--lw-dsh-ime, 0px)) !important;
}
html[data-lw-ime="on"] #root:not(:has([data-mobile-nav="frame"])) {
  box-sizing: border-box !important;
  padding-bottom: var(--lw-dsh-ime, 0px) !important;
}
html[data-lw-ime="on"] body { background: var(--dsw-alias-bg-base, #fff) !important; }
```

入口是 `window.__LUWI_IME__(px)` (px 是 dp, WebView 里 1 CSS px = 1 dp), 上限按视口 75% 夹 —— 与门户
`applyIme` 同一个防呆。变量名与门户分开 (`--lw-dsh-ime` / `data-lw-ime` vs `--lwp-ime` / `data-ime`), grep 才不混。

宿主那一侧 (`ui/HostScreen.kt`):

- `ImeLiftPusher` (单独一个小 composable, 逐帧变的只是它) 三选一: 门户 / 页面 / 安全网;
- 安全网取「连着两帧一样的值」(`IME_SETTLE_FRAMES = 2`), 一次键盘动画只写两回, 不逐帧;
- 探针 `imeTakesLift`: 300 ms × 20 问一句 `typeof window.__LUWI_IME__ === 'function'`
  (ui-fix 在页面 boot 里 apply, 比 `onPageFinished` 晚), 答 false 才退安全网;
- `readyAt` 进 effect 的 key: 文档换过要补推一次 (html 上的自定义属性随文档一起没了);
- WebView 上的 `setInsets(Type.ime(), NONE)` **保留** —— 正是它让 Chromium 不再缩可视视口 / 整页平移。

## 三、已知取舍

- `100vh` 尺寸的弹层 (快捷指令 / 设置弹层) 不再随视口变矮: 它们靠插件自己的 keyboard guard;
  问答卡 (`question-fullscreen`) 按旧的带高算, 而 Luwi 预设里 `tool-ask-user` 是关的。
- 插件不武装时 (宽屏平板 / 桌面指针) 走 `#root` 那条兜底, 行为与手机一致。
