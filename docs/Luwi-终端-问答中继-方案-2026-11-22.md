# Luwi 终端问答中继 — 方案 (2026-11-22)

主人原话: "当pc端使用问答工具时，手机端没有反应，有办法解决吗？是否可以在手机发给电脑的内容里加上提示词
或者问答也要传并默认使用自定义回答？"

## 1. 症结 (三条一起治)

| 现象 | 真因 |
| :-- | :-- |
| 手机完全没反应 | 问答卡片长在 **dsh 自己的会话界面**, 答案走客户端 remote event `user-questions/request`; 手机连的是它自己的 host, 永远收不到 |
| 连"电脑在问你"那一行都没有 | 手机终端画的是**投影会话**, 只由快照 `entries` (user / assistant 文本) 折出来; `ask_user_question` 是 `tool/call`, `condense` 只数次数、不折文本 |
| 就算插件写了, 手机也不来取 | 投影刷新判据是 `/peer/info` 的 `updatedAt` (账上叫 `revision`); 问一句不改会话日志 → revision 不动 |

结论: 卡是"电脑在等一个手机看不见的问题", 手机在等"电脑出下一句话", 两边一起卡到超时。

## 2. 四档

| `ask.mode` | 手机看得见 | 手机能答 | 超时/无人 |
| :-- | :-- | :-- | :-- |
| `off` | 否 | 否 | 电脑弹卡 (以前的行为) |
| `notify` | 是 (写明只能在电脑上答) | 否 | 电脑弹卡 |
| **`relay` (缺省)** | 是 | 是 | `waitMs` (缺省 120 s) 后按自定义回答继续 |
| `auto` | 是 (一行"我自己定了") | 否 | 立刻自定义回答 |

只对**手机驱动的那一场**生效: 收到过 `source.via === 'peer'` 的那一句, 或由 `target:{kind:'new'}` 新开的那场。
电脑本地那一场一个字都不动 (照旧 `next()`)。

## 3. 四条硬约束 (改这块之前先读)

1. **接管必须 `prepend`** —— dsh 自己的问答卡片也挂在这个 waterfall 上 (客户端 remote 监听), 谁先谁拿到请求。
   晚一步就只是"PC 弹卡、手机不知道", 等于没做。
2. **问题那一行是合成条目** —— `condense(events, {extra})` 在窗口裁剪**之前**并进 `entries`,
   **不进 `all`** (对话账 `conv/` 只记人话); `seq` 取那一笔 `tool/call` 的真号 (天然有序、天然幂等;
   自造的号会被后一条真条目跳过)。`LIVE_SNAPSHOT_VERSION` **不动** —— 条目形状没变, 老手机插件照样折得动。
3. **回答在投递之前结算** —— `receive()` 先问 `deps.answerAsk`。那一轮正卡在工具里, steer 进去要等工具返回才被读,
   而工具等的就是这句答案 —— 这就是"双方互等到超时"的成因。命中就地 resolve, 不进 agent inbox。
4. **正文一个字都不改** —— 终端提示走 `agent/pre-step` 追加的一条上下文消息 (`source.kind` 是本插件, 不是 `user`,
   所以 `condense` 会跳过它、手机上不多一行)。理由是回声去重只比"人话" (`pendingKeyOf`): 改一个字,
   手机就会把同一句画两遍。

## 4. 数据与人话

- 快照里那两行: `（电脑在等你回答，约 N 秒内没回应就按自定义回答继续）` + 选项清单 + 回法;
  答完补一行 `（已按你在手机上的回答继续：…）`。
- 超时那一句 (`AUTO_NOTICE`): 让模型按最佳判断继续, 并在正文写「我替你定了：…」。
- 终端提示 (`TERMINAL_BRIEF`): 这一场从手机来 / 能自己定就别问 / 必须问就一问一清单 / 用 1 或一句话答。

## 5. 落点

| 文件 | 干什么 |
| :-- | :-- |
| `lib/luwi-ask.mjs` (新) | 纯算术: `resolveAskSpec` / `askEntryText` / `askAnsweredText` / `parseAskReply` / `autoAnswers` / `renderAskState` / `createAskRelay` |
| `lib/luwi-live.mjs` | `condense` 多一个 `extra` (合成条目, 进 entries 不进 all) |
| `lib/luwi-peer-runtime.mjs` | `receive()` 在投递之前问 `deps.answerAsk`; 回执多一格 `answered` |
| `index.mjs` | 三条钩子 (`session/event` / `user-questions/request` prepend / `agent/pre-step`) + `ownSessions` 抬 `updatedAt` + `projectSession` 传 `extra` + `/sync ask` + doctor 读数 |
| `lib/luwi-configure.mjs` | `ask` 段写面 (`mode` / `waitMs` / `brief`, 逐键校验) |
| `lib/command-words.mjs` | `/sync ask` 的动作词 (中文正写, 英文别名) |

## 6. 手机端

**零改动**。问题走已有快照 (`/peer/info` → `/peer/transcript`), 回答走已有 `POST /luwi-sync/peer/send`。
没有新路由、没有新快照版本、不用重打 APK。

## 8. 真机验证待办 (还没跑)

1. PC: profile 里 `pnpm install` 让 `luwi-dsh-sync` 的 `file:` 依赖重新链接 → 重启 host; `/sync doctor` 应见 `问答: relay`。
2. 手机扫码进终端, 让 PC agent 问一句, 量它出现在终端页的秒数 (应 ≤5 s)。
3. 回 `1` (或一句话): PC 那一轮的 `tool/result` 是选中项 / 自定义回答; 手机上不出第二行。
4. 不回: `waitMs` 后按自定义回答继续, 正文有「我替你定了：…」。
5. `/sync ask 关` 再问一次, 回到 PC 弹卡。
6. 读数落 `logs/`、图落 `shots/`; 真机 A 不在线时按 AGENTS 用模拟器出开发项读数并标待真机复验。
