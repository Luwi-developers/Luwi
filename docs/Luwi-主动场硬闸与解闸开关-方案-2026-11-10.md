# 主动场硬闸 + 三档解闸开关 方案 (2026-11-10)

## 0. 一句话

借 QQ 桥接 `groupAtOnly` 那一手: 把"主动场能做什么"从提示词变成硬闸, 闸分三张表 (屏 / 写动 / 命令),
**三档**由主人一句话定: `remind` (默认, 全拒) / `act` (解写动与命令) / `full` (连屏一起放开).

## 1. 背景

QQ 桥接的经验: 群会话的唤醒条件被 `/api/socialV2/wake-config` **钳死**成"只认 @/引用",
其余一律清掉、`mode` 拉回 `diving` —— 硬钳制, 不是提示词.

Luwi 现在的"主动场只提醒"靠两样: proactive 预设 **plugins 里压根不装** bash / pwsh / tool-fs,
加上 persona 那几句"不可 shell / 不可写文件". 前者一合并预设就没了, 后者按项目口径
("审批全放行, 这层拦不住模型")不成立. 所以先把闸补硬, 再谈合并.

**本方案覆盖 13-4 的口径 (仅 `full` 档)**: 13-4 原定"主动场一条虚拟屏都不建",
现在按主人 2026-11-10 的决定改成**可开**: 默认仍不建, 第三档明确允许.

## 3. 设计

### 3.1 三张表

| 表 | 内容 | 说明 |
| :-- | :-- | :-- |
| **A 屏** | 现有 21 条: `lw_screen` / `lw_screen_create` / `_resize` / `_rotate` / `_release`、`lw_screenshot`、`lw_ui`、`lw_ui_dump`、`lw_ocr`、`lw_wait_text`、`lw_events_subscribe`、`lw_events_wait`、`lw_wait_for`、`lw_tap`、`lw_swipe`、`lw_type`、`lw_key`、`lw_key_combo`、`lw_gesture`、`lw_pinch`、`lw_scroll` | 建屏 / 读屏 / 在屏上动手 |
| **B 写动** | `lw_files`(仅 `op=write`)、`lw_app_control`、`lw_system`、`lw_launch`、`lw_intent`、`lw_download`、`lw_share`、`lw_notify`、`lw_clipboard`(写类 op)、`lw_automation`、`lw_plugin`、`lw_skill`、`lw_sync`、`lw_mode`、`lw_quickapp`、`lw_volume`、`lw_vibrate`、`lw_lock`、`lw_power` | 会改设备或外发 |
| **C 命令** | `lw_linux` + (合并预设后才会出现的) `bash` / `pwsh` / `fs`(写类) / `jobs` / `web` / 子代理 / `plan` / `todo` / `present` | 执行类 |

**B 表按 op 判**, 不整条拒:
- `lw_files`: `op === 'write'` 才拒; `list` / `read` 永远放行;
- `lw_clipboard` / `lw_app_control` / `lw_system` / `lw_automation`: 只放只读 op (`get` / `status` / `list`),
  其余按档位;
- op 取不到 → **fail-closed** (按"拒"处理), 不猜.

### 3.2 三档

`sim.proactive.acting`: `remind` (默认) | `act` | `full`

| 表 | `remind` | `act` | `full` |
| :-- | :--: | :--: | :--: |
| A 屏 (21 条) | 拒 | 拒 | **放** |
| B 写动 (19 类) | 拒 | 放 | 放 |
| C 命令 | 拒 | 放 | 放 |

- `remind`: 今天的形态 —— 只读 + 说话, 一条都不能动;
- `act`: 能写文件、开应用、跑命令, **但屏永远不碰** (看得见的事要主人自己点);
- `full`: 连屏一起放开 —— 她会自己建虚拟屏、截图、点、滑, 主动场与被动场的工具面完全一致.

读不到 / 值不认识 → 按 `remind` (最保守). 旧的布尔值做一次性迁移:
`allowActing: true → act`, `false → remind` (迁移只读, 不写回文件).

### 3.3 配置落点

`$DSH_HOME/lw/sim.json` 新增一段 (应用单写者 `tool/SimSetting.kt`):

```json
{ "proactive": { "acting": "remind" } }
```

不放进 `proactive.json`: 那份是宿主单写者 (`starts` / `run`), 配置与运行账不能混写.
`ProactiveSchedule.Plan` 不加字段: 排期与权限是两件事.

### 3.4 判定顺序

```
exec.name 命中 A ?
    acting === 'full'  → 放
    否则               → 拒 (档 remind: "这一场只提醒" / 档 act: "屏永远不碰")
否则命中 B ?
    acting === 'remind' → 拒
    否则按 op: 只读放 / 其它放
否则命中 C ?
    acting === 'remind' → 拒
    否则放
否则 → 放
```

- 判定每次读 `sim.json`, 带 **3 s 缓存** (mtime 变了才重读);
- 拒绝文案分档: `remind` 说"这一场只提醒, 要动手请在对话里说"; `act` 撞到屏说"屏永远不碰";
- 档位切换**不需要重启 host**, ≤3 s 生效.

### 3.5 与开场注入 / persona 的联动

`proactiveStartLine()` 现在写死"主动场不建虚拟屏", 必须按档位生成:

| 档 | 注入那一段 |
| :-- | :-- |
| `remind` | 不可 shell / 不可写文件 / 不可屏幕控制 / 不可 App 控制; 主动场不建虚拟屏 |
| `act` | 可以动手 (写文件 / 开应用 / 跑命令); **屏不碰** —— 要看要点的让主人来 |
| `full` | 可以动手, 也可以建虚拟屏、截图、点; 但动手前先说一句你要做什么 |

persona 保留"只提醒"的语气段, 档位换了只换那三句, 不改其它.
