# 终端图片与文件双向传 + 未配对装 PC + 取消配对 (方案, 2026-11-22, 2.8.1 #50)

> 主人三条原话:
> ① 要求终端显示图片, 图片与文件都要传, 在前台里要若本次会话带文件, 要显示在消息下方
> ② 要求在没有配对时扫码配对下加一个「去给PC装luwi终端」
> ③ 设置里要有取消配对功能

## 1 口径

- **媒体走「文件 + 附件段」, 不走 attachment 块**: 手机侧 dsh 的附件落盘在安卓上必失败
  (`client.js` 的 `imageBlocks()` 注释里记着真机读数), 而门户本来就会照正文里那一段
  `[附件 N 个, 图片用 read_image 打开]` + `1. /abs/path` 画真图与文件名 chip
  (`splitAttach` → `/lw-out/in/<名字>`, 宿主读 `<HOME>/lw-in`)。于是**跨设备只做两件事**:
  把字节搬过去, 把路径换成本机真实存在的那一条
- **手机 → 电脑**: 先 POST 到电脑的暂存区, 收话时再搬进**那一场工作区**的 `lw-in/`, 正文那一
  段名单换成电脑路径 —— 电脑那边的模型拿 `read_image` / 读文件工具就能打开
- **电脑 → 手机**: 快照条目多一格 `media` (附件块 id 或工作区路径), 手机取回字节写进本机
  `<HOME>/lw-in/`, 再把名单换成本机路径 —— 门户的画法一个字节都不用改
- **取消配对只断牵连, 不删数据**: 对端地址与口令删掉、四档闸全关、`pairing` 与 `role` 删掉、
  同步停掉; 对话、收下的附件、影子工作区目录都留着

## 2 数据面

`$DSH_HOME/lw/session-sync.json` 不变 (`peer.listen/acceptSend/proxy/url/token` 那几格).

新的两份账 (都只作缓存, 坏了不拖死任何一条主路):

| 文件 | 形状 | 谁写 |

| `$DSH_HOME/lw/peer-media.json` | `{v:1, at, items: {"<设备>|<会话>|<seq>|<id 或 path>": {path, bytes, at}}}` | 手机侧 `materializeEntryMedia` (原子改名) |

## 5 闸与边界

- 单份 ≤ **20 MB** (与 `BallMedia.MAX_BYTES` 同数), 一条最多 6 份; 超了明说一句, 不静默丢
- 上传只认 `<HOME>/lw-in/` 之下的文件; 下载只认那一场 `cwd` 子树 (外加上传暂存区); `..` / NUL / 非普通文件一律 404
- 同名不覆盖: `dedupeFileName` 顺延 `_2`; 暂存区名字前挂时间戳
- 对端老版本: POST/GET 回 404/405/501 → 降级成纯文本 + 一句人话, 不阻断文字
- 口令仍只在宿主: 门户 `/portalTerminal` 那份读数一个字节都不含 token
- 取消配对之后: `PortalTerminal.status` 的 `paired=false`, 终端卡片自己回到 `unpaired` 档;
  旧的影子工作区与投影会话留在盘上 (不删数据), 只是不再更新
