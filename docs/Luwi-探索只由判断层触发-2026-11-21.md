## 为什么还要再改一次

2026-11-21 第一次改口径之后，读数是这样（改之前逐条核过）：

| 设置页那一格 | 判断层那条路 | 结论 |
| :-- | :-- | :-- |
| 允许她自己探索 (`enabled`) | 一次都不读 | 空开关：关掉它，判断层照样 `startExplore` |

## 这次做了什么

1. **触发口唯一**：应用侧排期整套删掉 —— `ExploreSchedule` 里的 `arm` / `ensure` / `ensureIfStale` /
   `ensureCatchUp` / `nextAt` / `catchUpLateMs` / `dueOf` / `fire` / `fireAsync` / `unlockForExplore` /
   `report` / `Last` / `describeLast`，以及 `ExploreAlarmReceiver` 与清单里那条 receiver、requestCode 42、
   17 条 `settings_explore_*` 字符串（时刻 / 分钟 / 开关 / 上一次 / 没开成那条通知）。
   `explore-schedule.json` 只剩 `steps` 与 `unlock` 两键；老文件里的 `enabled` / `at` / `minutes` / `last`
   一律当没有（**老机器上关掉探索这个状态不再拦得住它** —— 这是"判断层唯一决定"的直接结果）。
2. **开场读卡**：宿主新增 `readExploreTask()` → `exploreTaskText()`（纯函数：去首尾空白 / 8000 字封顶 /
   读不到回空），`routerTick` 判 `say=true` 且球不在场时把卡当 `text` 交给 `startExplore`。
3. **步数生效**：宿主新增 `readExploreSchedule()` → `exploreStepsFrom()`（纯函数：缺键 / 坏值落 60，
   越界夹进 1~1000），`routerTick` 每场开场前现读一次；门户那颗「开始这一趟」也带同一个 `steps`。
4. **删两处读数**：设置页「允许她自己探索」整行；门户 `status.explore` 的 `schedule` / `enabled` / `nextAt`，
   改成 `steps`，抽屉那一行从「探索时刻 03:00 (每天)」改成「每场步数」。

## 边界的处理

- 屏锁着：不再有"到点先解屏"（那条随排期删了）。探索里那一次 `lw_lock op=unlock` 仍过设置页「允许锁屏解锁」
  （`LwLock` 那道闸没动），`presets/explore` 的 persona 也照旧要求"解不开就写进摘要，不绕"。
- 卡为空 / 读不到 → 开场回退「自由探索这台手机」，与以前一致。
- `explore-schedule.json` 读坏 → 60 步，不拒开这一场。
- 设步数只对**下一场**生效（宿主每场开场现读，正在跑那场不动）。
- 升级后在 AlarmManager 里躺着的老 42 号闹钟：receiver 已从清单删掉，系统静默丢弃；`save` 也不再 arm。
